# ADR 104: Read active recovery work and source-scoped restore records

Mode: reference. Date: October 11, 2026. Status: implemented candidate; production release and comparable billing measurement pending.

The authenticated Convex dashboard showed 47.38 GB of VibeScroller database I/O in the September 26 to October 26 period. Production `knowledge.recoverPage` contributed 4.58 GB and preview `recovery.applyMarkers` contributed 7.63 GB. The October 7 team invoice charged $9.02 for database I/O out of $10.60. These are accumulated observations, not a forecast or proof of savings.

Knowledge recovery keeps its five-minute cadence, twenty-record pages and existing dispatch/timeout behavior. Global state/updated-time indexes select queued work and expired running leases in both knowledge tables. Completed, unknown, canceled, stale, failed and deleted history, and healthy running leases, are excluded before document reads. A fixed sweep checkpoint travels with indexed continuations; newly updated jobs wait for the next sweep. A 512 KiB pagination read target bounds pages without truncating the sweep. Empty phases are probed through the index and do not start scheduled functions. Old unindexed continuation arguments restart against active work. Claim-time funding, membership, reference and version checks remain authoritative. Expired running work becomes unknown and retains its financial hold.

Source redaction selects assets through an organization/source index, and coding runs through their existing proposal index with an explicit workspace check. It still redacts canonical and derived content, retires every matching object key, fences execution generations, and preserves PR receipts. Markers are never skipped on the assumption that an earlier restore applied them. Reapplying a marker still scrubs resurrected content. Physical deletion receipts still release stored-byte accounting.

Evidence inventory and locked restore projections reuse document reads inside their immutable query snapshot through the existing query-local helper. Every subsequent query gets a fresh cache. Source generation, current deletion markers, workspace status, expiry and object retirement remain checked; no authority is cached between requests. Archives, object hashing, retention, restore lock and before/after-write fences are unchanged.

The three added indexes require no application-data migration. Existing indexes and document fields remain intact. Index storage adds copies of the affected records; measure net provider charges rather than equating fewer reads with invoice savings. Rollback may retain the additive indexes. Reverting the query would restore the expensive history scan.

Regression tests enforce a 64 KiB transaction read budget with large unrelated history, assets and runs. They cover all recovery phases over multiple pages, removal from an index during pagination, terminal and healthy-job exclusion, reservations, kill switches, legacy continuations, PR preservation, repeated marker application and fresh deletion/generation checks after query-local reuse. Existing knowledge, privacy, recovery and storage-accounting suites remain required. See implementation status and the usage runbook for actual verification and release evidence.
