# ADR 118: reconcile creator following and guided onboarding as planning-only scope

Date: October 23, 2026.

Status: accepted planning direction; implementation of these additions is not authorized.

## Context

The owner supplied a creator-following plan and onboarding storyboard initially inspected at `54a0b26`, with a later `d8e97a3` reconciliation note. The current completion branch already contains SetupJourney, CompanionSetup, librarySetup progress, exact permissioned public artifact reuse, source/evidence contracts and task-based Help/media. R1/R3/R7 corrections are in progress. The owner requests one implementation/integration owner and one remaining-work plan, continuing previously authorized work while keeping these feature additions planning-only.

## Decision

The [October 23 remaining-work plan](../launch-plan/2026-10-23/README.md#creator-and-onboarding-reconciliation) owns both existing R0-R13 work and new N0-N7 planning scope. Root retains integration, contract, budget and final-review ownership. Extend existing onboarding, job and public artifact/reuse systems; do not create parallel onboarding, inference queues or reusable-analysis stores.

The selected future direction is daily public TikTok/Instagram creator monitoring without creator cooperation; video, image, TikTok photo and ordered/mixed carousel evidence; ideas, lessons and summaries; independently eligible neutral shared analysis plus private personalization; eligible local own-subscription and approved cloud routes; future posts by default with optional latest ten posts under separate asset bounds.

The new project-builder sequence is ChatGPT processing connection, optional GitHub, three relevant verified skill recommendations, "Now we can vibe. Time to scroll.", explicit VibeScroll invocation through ChatGPT with copy/paste fallback, required Instagram export education and optional creator following. GitHub and skill installation are skippable. Show fewer than three recommendations if fewer qualify. Reaching and acknowledging the guide's final step completes education; export request and actual import can happen later. Persist these states separately, preserve existing progress and library access, and derive capabilities/results from real server state.

D14's arbitrary private-data reuse default remains. Existing ADR 111 exact published reuse remains valid. Automatic neutral internal reuse needs an explicit additional authority/lifecycle contract, rather than a duplicate cache or an assumed grant from public visibility, service funding or a local subscription. No private analysis migration follows.

N0-N7 require a later explicit implementation instruction. Current R0-R13 fixes retain their existing authorization. Planning does not select a supplier, install a skill, collect posts, schedule discovery, enable a provider or deploy code. The original cumulative US$2 ceiling, no-new-spending rule, provider/rights/privacy/isolation/release gates and exact publication approvals remain unchanged.

## Consequences and acceptance

The plan records current-code mappings, conflicts, owners, dependencies, future acceptance and new provider/cost evidence. The [ledger](../launch-plan/2026-10-23/ACCEPTANCE.md#planning-only-additions) retains the supplied A01-A24 scenarios. Synthetic tests, provider contracts, actual native-device checks, production verification and independent usefulness remain separate evidence. No addition is called implemented or released because it is documented here.
