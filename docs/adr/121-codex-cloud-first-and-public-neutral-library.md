# Prefer user-owned Codex Cloud and an eligible public insight library

Mode: decision. Date: October 23, 2026. Status: owner-selected direction and authorized investigation/planning; production activation remains gated. Read the [current implementation sequence](../launch-plan/2026-10-23/CLOUD-FIRST.md).

## Decision

The owner prefers official user-owned Codex Cloud for permitted link acquisition, media preparation and general analysis, using each user's own subscription. The goal is a mobile web experience without a required awake computer, Docker Desktop, VibeScroll-paid inference or an implicit managed-credit fallback. This is not permission to run a VibeScroll-hosted copy of users' subscription sessions.

Investigate and test the real link-to-cited-result path first. MCP Events is a candidate supported host notification mechanism, not proof of media capability or a general consumer task API. The first actual personal Cloud probe failed before shell execution despite a ready status. Its failure remains recorded.

After Cloud succeeds, the owner permits postponing the local route and managed-credit route from the immediate critical path. Until then, preserve tested behavior, existing work and honest unavailable states. Deferred Windows signing/runtime acceptance is not completed by removing it from onboarding.

For newly eligible public-source work, the standard analysis is generic and intended for a free public reusable library. There is no per-result private opt-out within that clearly disclosed contribution mode. Preserve required legal/privacy/removal rights, source licenses and applicable provider publication review. Do not automatically publish private uploads, legacy private results, private/sensitive/unauthorized personal data or unreviewed generations. Retain permitted public creator/source attribution. Quarantine pending review is a product release control while the exact policy applicability is resolved.

Private reanalysis can use the user's own context, prompt additions and approved skills. Keep proposals, repository evaluations, plans, notes and private customization out of the public base. Customization cannot change tool, security or funding authority.

Daily public-creator following remains in launch scope. Prefer one compatible analysis per immutable source revision across interested recipients. The desired random subscriber selection and failure handoff require a separate verified provider contract and explicit per-contributor recurring authority. No shared credentials, cross-account limit circumvention, speculative duplicate dispatch or silent paid fallback.

Public categories, source/creator discovery and a future graph derive only from eligible current public artifacts. Trend indicators need transparent sample coverage and denominators. Editing-style imitation and other provider subscriptions remain future scope. No universal creator-usefulness or demand claim follows.

## Superseded product preferences and retained boundaries

This supersedes ADR 117's immediate paired-computer-first preference, conditionally on verified Cloud capability. It extends ADR 118/119's internal neutral-cache direction toward a public generic library. D14/PRD R29's private defaults remain for legacy/private material and personal layers; a new reviewed public-mode contract is required before different defaults apply.

ADR 088 completion notifications do not grant analysis authority. ADR 111's exact public editions remain valid, including the seven already reviewed insights. ADR 120 ordered/private upload authority remains private. Reuse existing source/local-library tasks, creator watches/deliveries, publicArtifacts/publicImports and persisted setup; no duplicate stores or queues.

## Unresolved release prerequisites

- Repeatable official Cloud execution after the successful personal audio-plus-sampled-visual proof; image/photo/mixed evidence, actual app result validation, enforced resource/usage limits and cancellation remain open.
- Actual supported-host subscription/event/write-back acceptance, current account and recurring allowance controls.
- Provider permission for commercial orchestration, subscriber contributions and proposed failover. Personal capability is not product permission.
- Permitted collection and derived-output redistribution, public insight license/contributor agreement, applicable review/moderation/deletion and restore.
- No-GitHub beginner setup, actual mobile sharing and independent comprehension.
- The original cumulative US$2 budget and all conservative holds; no new recurring funding, supplier purchase or billing changes.

The [plan](../launch-plan/2026-10-23/CLOUD-FIRST.md) maps every R/P/N item, external prerequisite and conditional deferral. Future Claude Code/Gemini support gets its own provider contract, not an assumed interchangeable subscription adapter.
