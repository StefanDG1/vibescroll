# Recommend GitHub without requiring it for source analysis

Mode: decision. Date: October 24, 2026, Europe/Berlin. Status: owner-confirmed product requirement; Cloud setup acceptance remains pending.

## Decision

Recommend connecting GitHub in project-builder onboarding because authorized repository context enables project-specific recommendations. Keep a clear, usable "Skip for now" action. Users can analyze supported sources and read their cited general results without a GitHub account, connected GitHub identity, selected repository or repository permission. Skipping GitHub must not reduce general source evidence/coverage, trigger repeated blockers or mark the person ineligible for source analysis.

Only repository-specific evaluation requires the relevant connected, selected and authorized context. Without it, do not invent project fit or dispatch repository evaluation/coding. Preserve personal libraries, approved examples, skills skip paths, required Instagram export education, private work and ADR 122's Pro access/contribution/retained-copy rules. Source rights, processing-account eligibility, funding and user consent remain independent requirements.

## Cloud setup and friction

This applies to the preferred Cloud journey as well as the existing app's optional project step. A Cloud provider's repository-based environment wizard is an unresolved technical constraint, not permission to make GitHub mandatory indirectly. A processor recipe may use maintained public source internally if supported, but a route that requires the user to create a GitHub account, authorize GitHub or create/select a repository does not pass the no-GitHub Cloud acceptance.

Investigate supported hosted runtime and provisioning paths; reuse an existing compatible environment when available. Root owns versioned tools/configuration, readiness checks and diagnostics. Minimize active user actions and external context switches. Users complete their own required account consent/MFA; never automate consent approval, collect account credentials or bypass provider restrictions. Do not promise one-click or phone-only provisioning until actually verified.

Proposed guidance: "Recommended for project-specific suggestions. You can connect GitHub later." Pair "Connect GitHub" with "Skip for now". Derive readiness from an actual processing/result check, not from a visited setup page or connected repository. Existing persisted setup and Help remain the owners; no new wizard, queue or analysis store.

## Acceptance and current limit

Test a fresh user with no GitHub identity/repository: connect an eligible processing account, skip GitHub and skill installation, complete the required guide acknowledgement, save a permitted source and receive a cited analysis in VibeScroll. No hidden repository prerequisite, project-processing dispatch or fake fit. Reconnect GitHub later and verify that only then-authorized project capabilities become available. Repeat reload/workspace/device/account-revocation and Pro-access negatives.

Measure active actions, external switches, elapsed setup, human interventions and failure recovery with actual beginners; fixtures and the founder's repository-backed environment do not establish this acceptance. Current official Cloud setup and the one personal media proof do not yet demonstrate this no-GitHub path. Keep provider-gated claims unavailable rather than weaken the requirement or silently use paid processing.

The [current plan](../launch-plan/2026-10-23/README.md), C0/C3/C7 and N5/N6 own implementation and evidence. This update records planning only, with no runtime, billing, live policy, deployment, provider call or spending change. The cumulative US$2 cap and existing unknown holds remain.
