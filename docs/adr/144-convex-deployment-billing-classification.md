# ADR 144: Convex deployment billing classification

Status: billing classification reviewed by the release owner; secure logical release proof proposed for independent review. Date: October 24, 2026, Europe/Berlin. No deployment or budget release is recorded by this decision.

## Decision

Classify internal Convex source packages separately from customer file storage. The former archive guard assumed that code ZIP copies and their retention necessarily incurred customer file-storage and egress charges. The published billing formula and the corresponding source paths support removing that assumption for the narrowly reviewed deployment path. They do not establish that all administrative operations are free.

The implementation reference is the official Convex backend at `7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb`. This is a source-backed interpretation of the public hosted contract, not an attestation of the hosted binary or a settled invoice.

## Evidence

The [hosted log-stream documentation](https://docs.convex.dev/production/integrations/log-streams#current_storage_usage-events) gives the billing formulas: database storage uses the aggregated document and index totals; file storage uses user-file and backup totals. The [gauge producer](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/usage_gauges_tracking_worker/src/lib.rs#L279-L336) computes the database totals from user tables, excluding system and orphaned tables. Its file gauge uses the `_file_storage` tracker plus cloud backups, rather than measuring the Modules bucket. Sending system-table details in a separate event field does not add them to those documented billing totals.

[Source-package metadata](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/model/src/source_packages/mod.rs#L33-L58) is stored in the system table `_source_packages`; [module metadata](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/model/src/modules/mod.rs#L71-L91) uses the system table `_modules`. The actual [package uploader](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/application/src/lib.rs#L2609-L2625) receives `modules_storage`. [Final publication](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/application/src/deploy_config.rs#L798-L812) reads packages through that same storage.

Customer file bandwidth is explicitly metered by the [file-storage wrapper](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/file_storage/src/core.rs#L275-L372). Its raw-upload comment explains that uploading bytes alone does not count toward usage; the caller must persist the file entry and account for usage. The source-package upload/download path uses raw storage instead of those customer file wrappers. Therefore archive copies, internal reads and old-package retention do not themselves imply a charge in these customer billing categories. No retention duration is inferred from the separate 230 MB code-size limit.

Deployment [module analysis](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/application/src/application_function_runner/mod.rs#L1738-L1840) calls a separate analyzer without normal UDF execution accounting. Its [Analyze response](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/npm-packages/node-executor/src/executor.ts#L477-L532) contains registrations or errors, rather than the duration, memory and egress usage fields returned for action execution. Internal analyzer retries are not additional customer action invocations under this reviewed path. Actual application functions and file operations retain their normal billing.

## Release constraints

The first compatible candidate preserved the deployed dependency lock. Its metadata inspection completed at 13:24:19 UTC with 12 components, 131 tables, 273 indexes and no schema or index changes. Publication remained undispatched. A fresh dependency audit at 13:27 UTC found high-severity Zod, body-parser and Undici advisories, so that candidate and its metadata remain frozen and unpublished.

The proposed secure candidate starts from the compatible frontend dependency tree, includes the reviewed deletion fix, and retains the deployed schema and component configuration. Only `convex/assets.ts`, `convex/privacy.ts` and `convex/integrations.ts` differ from deployed backend `abfdeff6779a2fc7790d4441152117262965fe60`. The release owner reported a fresh audit with zero high or critical findings at 13:37:42 UTC. Full main and its migrations remain held.

Patched dependencies can change PNPM's physical component-definition paths. Convex's [component schema preparation](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/model/src/components/config.rs#L247-L335) matches instances by parent and logical name, reuses their component IDs, then reads each proposed schema through its new definition path. An identical schema [returns its existing active schema ID](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/database/src/bootstrap_model/schema/mod.rs#L332-L349). These paths support a logical compatibility proof without treating a changed package directory as a new component instance.

The private replacement must preserve the original `evaluate_schema` response, including missing component predictions. Supplemental evidence must independently cover all 12 logical components, 131 tables and 273 indexes. It must verify stable active component IDs, arguments and HTTP prefixes; full active schemas and actual table mappings; enabled validation; and no in-progress or staged schema work. The supported [read-only evaluation path](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/application/src/deploy_config.rs#L373-L383) discards its schema transaction. Require its `schemaChange` to contain all 12 distinct schema IDs, empty `allocatedComponentIds`, explicitly empty index diffs and a complete zero-timeout readiness check. A changed schema creates a pending ID in the discarded transaction and cannot satisfy that readiness proof. Retain both original and supplemental evidence; do not manufacture a complete original prediction.

The guard must bind the exact clean candidate, patched lock, prepared module manifest, expected physical-path mapping and approved supplemental evidence. Preparation and inspection cannot publish. Publication requires separate root activation and fresh matching evidence for the same prepared public request. The actual start response must match the evaluated schema change. The secure candidate has not yet passed that hosted inspection.

System metadata probes retain an operation contingency. The [usage counter](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/usage_tracking/src/lib.rs#L218-L267) excludes system UDF call counts but explicitly retains bandwidth. The [database read tracker](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/database/src/reads.rs#L341-L378) excludes system-table reads from its database-egress counters. This supports a narrow classification for `_schemas`, `_components` and table-mapping metadata.

The current [official Data egress definition](https://docs.convex.dev/production/usage-limits#available-metrics) covers file downloads, outgoing fetches and log-stream egress. The pinned [NetworkBandwidth producer](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/usage_tracking/src/lib.rs#L516-L524) consumes `stats.fetch_egress`; its [network aggregate](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/usage_tracking/src/lib.rs#L1011-L1039) sums that same map. The [HTTP query handler](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/local_backend/src/public_api.rs#L434-L478) exports the returned value as JSON. Its application and runner path reaches the [cache return step](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/application/src/cache/mod.rs#L485-L524), which logs the tracker before copying the result. No returned-byte increment enters that map on this traced path. The exact metadata handlers and their system wrappers perform no external fetch, file serving or custom audit-log write.

Accordingly, this reviewed path supports excluding those exact query-return bodies from customer Data egress. It does not establish a universal HTTP-response exemption or attest the hosted binary or invoice. The US$0.25 proposed contingency is retained without a return-byte calculation. A generic 16 MiB developer-return limit is not a valid bound for system UDFs: the [result validator](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/isolate/src/helpers.rs#L117-L149) selects a separate system limit with a [configurable 24 MiB source default](https://github.com/get-convex/convex-backend/blob/7b7b58ed4afa1f9d07fa0b67b871ef8771c868eb/crates/common/src/knobs.rs#L401-L410). Neither a client reader cap nor that value-size limit is used as a wire-billing bound.

Keep exact deployment authorization, bounded control calls and payloads, phase ordering, durable reservations before dispatch, response ceilings and a single push. Refuse application functions, external Node dependencies, exports, inference, deployment fallbacks and retries after an uncertain transport. Response-reader limits protect the client; they are not a claim about server wire billing. Preserve every prior unknown hold and the cumulative US$3 ceiling. The revised operation envelope and any reassignment of definitively undispatched publication funds require their own recorded reservation before dispatch; this ADR does not create one.

## Validation boundary

Private guard validation uses synthetic offline transports. Hosted prediction, exact-head checks, independent review, activation, publication and production verification remain separate evidence. No source-package billing classification can substitute for migration safety or authorize deployment of the larger candidate.
