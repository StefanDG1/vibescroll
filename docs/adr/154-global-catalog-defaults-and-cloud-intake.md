# ADR 154: global catalog defaults and one-time Cloud intake

Date: October 25, 2026. Status: owner direction accepted; remaining implementation and production acceptance required.

## Owner decision

The owner confirmed that normal generic analysis contributes to one global proprietary catalog for paying users. There is no region selection or per-post sharing opt-out in that flow. Teams remain collaboration settings, not a destination choice for generic insights. Personalization, private notes, repository context, proposals and plans remain private.

Removing a post from a personal account removes its saved association and private material. It does not delete the shared canonical result, including when the last personal association is removed. Users cannot use ordinary post deletion to erase the catalog. Actual source-rights expiry, privacy erasure, safety and moderation are separate canonical-removal paths. Their current controls remain in force.

The desired input is a shared link. Setup should happen once. No routine reconnection, per-post handoff text, repeated publication approval or region picker belongs in normal use. Existing source, authority, entitlement and quota checks run on the server. Actual provider reauthentication or required Internet consent cannot be fabricated or bypassed.

## Use the current host when it is already running

A link sent to a ready Work Cloud chat already gives the host a user turn. Within the user's requested analysis workflow, the existing tools can save the link, read exact status, request the specific Cloud job, claim it, acquire and inspect media, bind preparation, complete and fetch the result. GitHub and a local computer are unnecessary. No second message or pasted handoff is inherently required for that inline tool chain.

Keep the current exact-source grant and job checks. Metadata instructions do not authorize background processing or upgrade existing grants. A saved result can be read without another model run. Unsupported hosts must report their missing capabilities before requesting/claiming work, without switching to local or paid processing silently.

## Wake the host for work received outside the chat

Links saved directly in VibeScroll and creator-monitoring deliveries need an actual host trigger. [Official MCP Events](https://developers.openai.com/plugins/build/mcp-events) supports signed webhook subscriptions in Work on web and desktop with Cloud selected. Extend the existing grants, subscriptions, deliveries and source jobs with a versioned waiting-work event and separately reviewed standing authority. Bind source/job identity, current actor/grant and bounded settings. Preserve deduplication, expiry, revocation, no restart after unknown execution and completion-loop prevention. Prove callback delivery **and** an operational media runtime; a webhook acknowledgement is insufficient.

The [Workspace Agents trigger API](https://developers.openai.com/workspace-agents/trigger-runs) is another documented route for published agents, with [admin-enabled scoped tokens](https://developers.openai.com/workspace-agents/authentication). Personal Pro availability and funding are not established for this account. A read-only inspection showed Pro and no available Admin/token/Workspace Agent entry. Do not add an account, purchase a plan or use the paid Platform Agents API as an automatic substitute. The internal Codex thread-message tool is not a public VibeScroll integration.

## Give canonical content independent ownership

Reuse `publicArtifacts` as the canonical store and `publicImports` as personal associations/snapshots. Add a versioned independent service-authority contract for newly admitted neutral artifacts. It must freeze stable source/content/evidence identity, compatible route/prompt/settings/language/coverage, verified reuse-policy identity, retention and moderation authority. It must not require the contributing account or personal source to remain live merely to read the canonical result.

New canonical ownership must be outside a user's purge scope. Account association removal, organization purge, catalog/saved-copy reads, source expiry and safety invalidation must change together. Merely skipping one deletion call would leave the existing live-source/account dependency and is incorrect. Existing private-only Cloud outputs are not silently republished.

The fresh13:35UTC prediction found zero `publicArtifacts` and `publicImports` records. The owner permits removing unnecessary compatibility while preserving saved posts and insights. Implement the service-artifact contract directly for this empty service store; preserve the separate legacy-edition branch and all existing source/knowledge data. Do not add a duplicate service store or permanent old-service fallback solely for unshipped fixtures. A fresh publication check must re-establish the empty service scope or stop for explicit migration review.

Connect neutral completion to the existing artifact producer and transactional deduplication. Attach its personal association to the existing saved post, rather than creating another text stub. Use stable media/content identities instead of private task IDs, grant IDs or retention timestamps as cross-user compatibility. Never manufacture a managed-provider receipt for own-subscription work. Contributing does not grant Pro access.

Keep advanced public editions, approved examples, collections and globe features separate from default catalog contribution. Move their deliberate publication/region controls out of the ordinary analysis journey without making the proprietary catalog public. Default status should state whether a result was reused, is processing, is available or is blocked by an actual policy. Do not claim automatic contribution while it is unimplemented or quarantined.

## Dependencies and acceptance

Root owns shared contracts, integration and final review. Execute the following through reviewable stages:

1. Clarify the existing inline Work Cloud tool chain and setup without changing authority or falsely claiming host launch.
2. Implement independent canonical authority and association-only deletion together, with privacy/moderation/expiry tests.
3. Implement one-time standing settings and supported event subscription through the existing setup, grant and delivery systems. Then connect save/creator intake to existing jobs and neutral contribution.
4. Preserve global paid access, saved copies, current source/Apply/private-overlay actions and every original R/P/N/C/M acceptance. Complete Home/Library/loading and other retained launch work in their existing dependency order.
5. Publish only with fresh schema/index impact, a conservative funded bound, exact-head CI and staged/canonical verification. Distinguish real media results, an inline turn, an event wake, automatic display and general release.

Tests must prove that A removing their post/account leaves B's valid shared result and saved association, while genuine canonical takedown blocks all derivative reads. Also prove content-version compatibility, private-data exclusion, concurrent request deduplication, one-time setup/renewal, supported host execution, no GitHub, no paid fallback and honest unresolved usage.

The same cumulative EUR5 cap and all earlier unknown/future obligations remain. The completed read-only full-main prediction found no validator walks, but five populated index backfills. It did not authorize publication. No customer, subscription billing acceptance, automatic background run or 100% completion is claimed.
