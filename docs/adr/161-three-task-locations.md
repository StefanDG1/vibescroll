# ADR 161: three clear task locations

Date: October 26, 2026. Status: owner-directed implementation candidate.

## Problem

The existing labels use Cloud for both the user's ChatGPT subscription and VibeScroll's credit-funded processing. Setup emphasizes the paired computer and hides the distinction behind technical controls. The owner wants three understandable choices, setup shortcuts and honest disabled states.

## Decision

Use one shared **Where tasks run** picker in Save and Continue setup, in this order:

1. **My own Cloud Work**, using the user's ChatGPT subscription, Recommended.
2. **VibeScroll's servers**, using credits bought separately.
3. **Local machine**, using the user's own eligible subscription and an awake paired computer.

Give each a short description, status, Finish setup or Reconfigure link, and tap/keyboard-accessible More info. Keep Save without analysis separate. Recommendation expresses the selected direction; it does not grant availability, consent or spending authority.

The first choice stays disabled until automatic native-event media execution is accepted. Existing server/local choices retain their actual feature availability and all current account, model, isolation, quote and per-task checks. Selecting a location changes a preference only. Do not activate a route, add a paid fallback, widen grant8, or change a credit balance to populate the picker. Preserve saved routes and all source data.

Use existing Connections, Usage and Paired computers pages for setup. Remove the duplicate inert Prefer my ChatGPT plan checkbox from Connections while preserving its historical stored value and API. Pairing alone is never shown as runtime readiness. The existing private-owner preference is returned through the authorized AI-preference read and used when opening Save. Unavailable preferences never choose a different route. The Save editor refreshes its existing bounded workspace options once when opened. No new stored database field, table, index, service or provider registration is required. Update Help and the project-builder lesson to use the same terms.

## Automatic analysis direction

The preferred next implementation is native Work-host media acquisition after an exact, finite app-Save intent under a separately reviewed versioned grant. Reuse the existing source job and lease after runtime preflight. A save notification alone cannot authorize analysis. Shared capture, creator capture and MCP saves cannot inherit app-Save permission. Preserve ready, active and unknown results, exact input hashes, retention and no automatic fallback.

Do not create the short execution job before the host is ready. Do not add another queue or scheduler. Server extraction remains a separately priced second choice, not an undisclosed dependency of the recommended own-subscription route. The runtime bootstrap, actual image viewing, enforced decoder isolation, acquisition policy and full Save-to-analysis acceptance are still required.
