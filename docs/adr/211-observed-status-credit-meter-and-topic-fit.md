# ADR211: observed status, credit meter and topic fit

Status: first subset deployed atb8162b5, October30,2026.

## Decision

Adapt pinned MIT assistant-ui standalone AgentPlan/ErrorState to VibeScroll's existing job state. Do not install a second chat runtime to display pipeline work. Expose only observed stages and approved recovery actions. Keep indeterminate progress; an unknown outcome cannot offer an automatic retry. Failed reanalysis leaves the incumbent available.

Use CostMeter-style segments for actual used, reserved and available integer credits in unexpired pools. Expired unresolved holds are separate. Never infer total use from ten ledger entries, label all pools as one monthly allowance, change tariffs or reinterpret legacy credits. This presentation settles nothing.

Suggested-project scores use topic-coverage-v1: distinct post topics matched against confirmed project purpose/audience/goals/features, divided by distinct post topics. Each topic has equal weight; round only the displayed aggregate out of100. Keep integer counts for ranking and deterministic ties. Non-goal/constraint/evidence sections do not contribute positive matches. The first implementation retains the three-candidate bound and exact source analysis-version binding. Match terms come from the existing finite category dictionary, not copied repository text.

The disclosure explicitly names topic fit. It is neither code inspection nor predicted benefit. The owner wants a prominent proposal action for strong matches; do not add an artificial positive baseline. Missing history/priority/activity is not a positive signal. The [standing plan](../design/ASSISTANT-ELEMENTS-AND-PROJECT-FIT.md) preserves bounded similarity, prior-proposal/outcome data, duplicate avoidance, meaningful activity, rubric versioning and caching for later work.

The website and compact MCP reader share the same controls and deterministic rubric. Advanced settings stay on the website. Tooltip/icon-button and provider-logo integration remain planned alongside the supported model catalogue. Shared presentation does not change OAuth, source access, credits or implementation authority.
