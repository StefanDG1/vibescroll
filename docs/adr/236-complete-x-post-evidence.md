# Complete X post evidence

Date: November 10, 2026. Requirement R161. Implemented and accepted in the bounded four-post production set on November11. See the [production receipt](../operations/evidence/launch-20261111-x-post-production.json).

The owner requests production X post support with gallery-dl first, FxTwitter fallback, then saving and analyzing the four previously benchmarked posts. The benchmark established complete text and matching media manifests from both providers on those four posts. It did not establish production integration.

Use the existing server-preparation pipeline. Invoke gallery-dl 1.32.19 as a separate CLI inside the acquisition microVM, with hash-pinned pure Python wheels, ignored user configuration, no cookies and no account credentials. One FxTwitter v2 request may recover a transport or parser failure. Authentication, access, rate-limit, identity and unsupported-media failures stop preparation. External links, quoted posts, replies and conversations are not additional acquisition jobs.

Canonical identity is the X status ID. A `/video/1` or `/photo/1` link selects the entire post. Keep complete text and each direct attachment in the new `service-prepared-post-v2` / `neutral-post-evidence-v2` protocol. Preserve old video protocol invariants. Full text is hashed and chunked only for citations; concatenating caption records reproduces the original text exactly. Caption and still-image references have null times. Every video has its own asset identity and local timestamp origin.

All declared direct images, MP4 videos and animated GIF videos must download and decode. Missing, inconsistent, inaccessible or oversized attachments fail the whole preparation instead of producing a complete result. Text-only posts are valid. Limits are 60,000 UTF-16 text units, 35 attachments, 50 MiB of aggregate original media, 600 seconds of aggregate video, 48 retained JPEGs and 240 speech segments. Images receive one retained JPEG each; each video receives up to eight sampled JPEGs. Raw media and temporary CDN URLs remain ephemeral. Retained evidence contains full text, attachment hashes and metadata, screenshots, and timestamped speech when present. This is complete attachment acquisition with sampled video evidence, not continuous visual inspection or permanent original-video hosting.

The existing restricted HTTPS broker handles acquisition. The same microVM then switches to denied network access before ffmpeg/ffprobe decode. Gallery dependencies are fetched and verified by the trusted controller, then unpacked without install hooks. gallery-dl is GPL-2.0-only, runs as a separate unmodified program and retains its upstream wheel licence. VibeScroll does not copy its implementation into the application. Dependency updates require a reviewed version, URL and SHA256 lock change.

Reuse preparation credits and the selected analysis executor. A zero-duration text/image post uses the minimum analysis credit band when API reasoning is explicitly selected; its actual evidence duration remains zero. No speech means no fabricated transcript. Multiple video audio parts use distinct speech IDs and one aggregate funding envelope. Private X evidence is excluded from the existing Instagram/TikTok catalog permission policy.

Production changed no schema, index, auth, component, cron or billing product, and made no provider purchase. Release and the four completed owner analyses used the bounded existing infrastructure reservation. Preserve prior unknown outcomes and holds. Verification must distinguish synthetic contract tests, actual hosted acquisition, saved ready analyses and user-host acceptance.
