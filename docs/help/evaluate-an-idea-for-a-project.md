# Review an idea for a project

The goal is a considered decision, including a reason to do nothing. Connecting a project is optional.

## Before you start

Have an inspectable source and permission to connect a destination repository. Your account needs a usable evaluation route and current project context. A repository used as a knowledge source does not automatically become a coding destination.

## Review the fit

1. Open **Projects** and connect GitHub if necessary. The GitHub App and selected repository access are separate from signing into VibeScroll.
2. Select the repository you intend to improve. Review its purpose, audiences, goals, constraints and current snapshot/context. Confirm or correct it before evaluating an idea.
3. Select the source or insights to review. Inspect the evaluation route and budget where processing is requested. Assistant retrieval alone does not authorize new inference.
4. Read the result beside the source and repository evidence. Check current behavior, suggested change, assumptions, alternatives and risk.
5. Keep distinct outcomes: useful, no fit, already implemented, deferred or insufficient context. If the context is stale, repair it before trusting an old assessment.
6. For a useful result, review a private plan when available. Edit or export it through the plan controls. You can hand it to your preferred agent or keep it for later.
7. Stop and decide. Accepting an idea or retaining a plan does not approve coding or public publication.

## Apply a whole post

Open **Applies to your projects** on an analyzed post. All extracted insights are selected initially. Use **Advanced · choose main points** to narrow them.

**Include full transcript and images** starts on in the supported group-evaluation controls. It adds the retained transcript, caption and available sampled image pixels. Turn it off to use extracted insights and citations with less input usage. This does not guarantee a particular charge or speed. Missing or expired images are reported; the original post is not downloaded again. A visual observation or image hash is not an available image.

Review the project and processing route before approving. One post can produce up to five distinct proposals per project, each with its own citations and review. Closely related ideas can form one proposal. No fit and already implemented remain useful results. Subscription groups require an updated compatible worker; older workers cannot claim the new tasks. A managed route can have a smaller image limit and stops rather than silently dropping images or switching providers.

## Use a private text result

In your private Library, open a source's private result. Select the private insights you want to evaluate, then choose **Review selected ideas for projects**. You can select up to twelve ideas. The controls use the actual result version you loaded, not its text pasted into the generic source analysis.

Choose a confirmed project, a compatible connected computer and an available model. Review the selected result version, project and quote before approving. The worker must support private project results. Update and reconnect it if that route is unavailable. Opening or exporting a result starts no processing.

Private project decisions and plans keep their private source version. They do not update shared generic analysis. If the source, rights, selected result or project context changes, review a new quote. Accepting a proposal still does not approve coding or publication. Private text analysis without a project does not require GitHub; evaluating a destination repository needs its connected current context.

## You have finished when

You can explain the decision with one source reference and current project context, and you have retained the reason or an editable next step.

## Before coding or publishing

Coding has a separate approval for the repository, base commit, exact plan, executor, funding route and maximum. Inspect the final patch and checks before approving a draft PR. An issue, draft PR, merge, deployment and measured benefit are separate facts. [Read the action boundaries](/help/actions-and-publication).

## If you get stuck

- Repository missing: inspect the selected GitHub account, installation and repository permissions.
- Context needs review: confirm the current draft or prepare updated context. Do not overwrite your own corrections with an AI guess.
- No fit or already implemented: keep the explanation. A useful decision need not generate code.
- Insufficient context: supply or confirm the missing bounded evidence before retrying.
- Changed repository or source: treat the old decision as historical until its currentness is established.

**Tip:** Review one concrete idea against one current project before attempting a broad batch.
