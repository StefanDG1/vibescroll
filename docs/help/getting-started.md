# Get started with one saved source

Your library is useful on its own. You can save a link before connecting GitHub or an assistant.

## Before you start

Use a phone or desktop browser. Reading this help and the [synthetic example](/example) needs no account. Saving your own material needs a signed-in workspace and a role that permits capture. Only submit material you are allowed to process.

## Take the short path

1. [Open your library](/app) and sign in with an email code or Google.
2. Choose one permitted source you want to find again. Use **Save** to paste a link, upload permitted media or supply text.
3. Review the available route and its maximum before starting analysis. **Save only** remains a useful choice. Saved metadata is not a completed analysis.
4. Open a ready result and inspect its evidence and coverage. [Follow the first-insight guide](/help/first-useful-insight).
5. Find it again in Library. Correct its filing if needed. GitHub is optional.

## Choose how work runs

Personal analysis needs an eligible paired computer, its working local runtime and that person's connected official account. It can wait when the computer is unavailable. Local preparation can send text and sampled frames to the model provider. It is not entirely offline AI.

An enabled managed route uses VibeScroll credits and explicit limits. A cloud route needs no paired laptop. Availability and quotas differ by account. VibeScroll never silently changes a waiting local task to paid processing.

## Continue setup without starting work

Your private library's **Continue setup** control remembers the selected route and optional reviews. Choosing a route, reviewing preferences or pasting a local prerequisite report starts no analysis and grants no startup permission. A local report is your supplied metadata, not an independently verified installation. Pairing, account access, an available worker and a cited sample are separate steps.

You can keep saving while a processing route is unavailable. New direct-source, public-community and installer features may still be release-gated. [Open-source setup](/open-source) distinguishes source preparation from available signed downloads; local package tests alone do not establish a released installer.

## You have finished when

You can reopen the saved source and explain whether it is saved, waiting, failed or ready. If it is ready, you can identify the evidence behind one insight.

## If you get stuck

- No usable route: keep the source saved and check **Connections**. [Repair setup](/help/processing-and-recovery).
- No Save control: your role may allow reading only. Ask your workspace owner about the task you need.
- Want the longer route: review purpose in your private library setup, then Connections, computer readiness and optional Projects. You do not need every connection for first value.

**Tip:** Start with one short source you already understand. That makes omissions easier to notice.
