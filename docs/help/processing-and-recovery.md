# Processing, costs and recovery

Keep the saved source while you repair the smallest missing prerequisite.

## Choose where tasks run

Open **Connections** and choose where tasks run. The Save form uses your chosen route:

1. **My own Cloud Work**, recommended. This uses your ChatGPT subscription in ChatGPT Work with Cloud selected. Your computer can be off. The private pilot requires current connection permissions, setup and a monitor. The choice stays disabled when these are unavailable; wider automatic-video acceptance is still pending.
2. **VibeScroll's servers**. This uses processing credits bought separately from your ChatGPT subscription. Review the maximum before starting. Buying credits does not enable an unavailable processing route.
3. **Local machine**. This uses your own eligible subscription on a paired computer. Keep the computer and its companion on. Review any preparation credits before starting.

Select one route to see only its setup. **Continue** saves the standard library, action and result preferences. Optional restrictions are under **Advanced settings**. In the Save form, **Manage setup** closes the dialog and opens the relevant page. Existing provider, workspace and budget checks still apply.

![Task locations in a synthetic account](/help/task-locations.png)

Choosing My own Cloud Work makes supported new video saves request analysis automatically; there is no second analysis checkbox. Choosing the route alone starts no video job. An explicit save-only request still saves without analysis. VibeScroll never switches a failed task to a different subscription or credit route automatically.

## Set up automatic Cloud saves

These steps apply when the private pilot is enabled for your account. A native saved-link event can wake the prepared Work task. Complete video-to-result acceptance and general availability remain separate.

1. In ChatGPT, connect **VibeScroll** using its normal sign-in and consent. Reuse your existing working connection. You do not need to delete it or create a second test connection.
2. In VibeScroll **Connections**, select **My own Cloud Work**, choose the model and press **Continue**. Standard setup includes current and future library posts, confirmed projects and supported ordinary actions. Results stay until deleted. Actual OAuth scopes and workspace roles still apply. You can narrow access in **Advanced settings**, or disconnect anytime. A normal signed-in session is enough; no fresh five-minute sign-in is required.
3. Open **Finish or resume ChatGPT setup**, copy the current setup message and paste it into your own ChatGPT Work chat with Cloud selected. Let its tool checks finish. A first setup may need tools or a speech model. The pinned cache verifier handles wheel metadata correctly; a failed integrity check stops setup without deleting your cache.
4. Wait until that chat reports **Monitoring** for new saved links and approved reanalysis requests. The current setup uses both native event types in the same Work task. Its supported subscriptions renew automatically. You can close the chat tab and turn your computer off. Reconfigure if you revoke access, change the reviewed grant, lose host capabilities or ChatGPT asks you to sign in again. Renewal is not a promise that a revoked connection works forever.
5. In the app, choose **My own Cloud Work**, paste a permitted Reel or TikTok, confirm your right to process it and choose **Add and analyze**. Save opens its post page. The link remains saved while the task checks readiness; a waiting state is not completed analysis. Inspect the actual transcript, images and citations when a result returns. Bookmark its separate post URL or reopen it from **Posts**.

The monitor must be ready before normal saves. A source that needs unavailable speech recognition or cannot be accessed stops without paid fallback. Keep the existing post while checking the reason in ChatGPT. A failed or unknown analysis is not automatically replayed.

## Saved results and temporary files

Completed analysis, transcripts, sampled screenshots and version history stay until deleted by default. Temporary source downloads, upload links, task leases and login tokens expire separately. Keeping a result does not keep a worker active. Explicit shorter limits in Advanced remain available. Shared neutral results can remain in the catalog independently of one user's saved copy; personal notes and project proposals stay private. Removing or taking down catalog content still blocks access.

## Before you start

Open the existing source/status link and **Connections**. Check which workspace and account you are using. Never send tokens, pairing secrets, signed links or private transcripts to support.

## Computer unavailable

1. Start your supported paired computer and the documented assistant worker.
2. Check Docker/local engine, offline transcription files and the saved official-client connection.
3. Confirm that the worker belongs to this user and workspace. Paired, account connected, worker available and ready to process are different states.
4. Leave waiting work queued. An idle worker can take up to five minutes to check for new work. Sleeping hardware does not wake automatically.

Stopping the worker pauses local processing. Revoking assistant authority prevents later claims. Unpairing, local logout and cancellation affect different permissions. Use the relevant control deliberately.

## Check local prerequisites

**Continue setup** shows commands to run on your paired computer. Replace `ABSOLUTE_CONFIG_PATH` locally; do not paste the real path or protected configuration into the browser. The preflight command prints a metadata-only prerequisite JSON report. Paste only that report into the labelled setup field if you want to record it; omit configuration, credentials and raw command logs.

The report is user-provided and its web acknowledgement expires after 24 hours. Even an all-passed report leaves processing readiness, account/model access and a cited sample separately unverified. Browser instructions do not read back actual pause/startup state. Resume and Windows sign-in startup require their own explicit local consent; saving a report does not enable them.

The companion package/update engine is candidate code. Do not treat local package tests or a source archive as a published signed installer. A usable distribution needs its actual release signature, approved runtime metadata and verified installation prerequisites. [Open-source setup](/open-source) explains the distinction.

## Account or permission changed

Reconnect through the supported sign-in flow when required. Use **Continue** in Connections to save the standard preferences. A normal signed-in session is enough. New OAuth connections initialize ordinary access automatically; existing custom restrictions and disconnections are preserved until you choose to change them. Never reuse another person's account or credentials.

## Understand the credit display

An estimate predicts possible usage. A reservation holds allowance before work. Settled usage records accepted costs. Pending or uncertain usage is not a final charge. Check **Usage** for remaining unexpired allowance and outstanding holds.

Personal ChatGPT allowance is separate from VibeScroll credits. Local preparation can still send evidence to the provider. Transcription, storage and cloud execution have separate requirements. Explicitly selecting a credit route is required; a local failure never silently funds it.

## Retry safely

If **Retry using Cloud defaults** is offered on a failed post, it starts one new request using your saved settings. Complete or resume Cloud setup first if prompted. VibeScroll offers this action only when the previous request was never claimed. It keeps the earlier attempt record and funding hold. Selecting Cloud does not fund a paid API fallback.

In ChatGPT, ask VibeScroll to retry that saved post. The assistant checks its current status and uses the same retry action. It cannot reset an unknown or previously claimed execution. A completed post uses **Reanalyze** to create a separate analysis version while keeping its current result.

Check the existing source first. If completion is unknown, reconcile its status rather than submit duplicate work. Reuse accepted prepared evidence where supported. A retry still needs current permission, source revision and funding approval.

For a GitHub or Reddit source, explicitly check the request status, recorded requests/bytes, omissions and any retry time. There is no hidden provider retry. If rights or retention ended, review your permission again and prepare a fresh request; GitHub needs a fresh pinned file selection. Old evidence and approvals do not become current merely because you retried. Supplying permitted text is a separately labelled recovery path, never proof that direct provider retrieval passed. Retrieval and analysis remain separate actions.

## You have finished when

The source has a clear saved, waiting, ready or actionable failure state, and you know the next repair and any approved maximum.

**Tip:** For support, record the app version, UTC time and safe error code. Describe the state without sending the source itself.

## Manual Work Cloud diagnostic preparation

This private test route appears only for eligible configured accounts. General public Cloud access remains unavailable until its separate release checks pass. You do not need GitHub or a paired computer to analyze a source in an eligible official Work Cloud task.

1. Open your own official Work Cloud task and select the requested supported model. GitHub is optional for source analysis.
2. Before approving a post, ask the task to check shell access, current restricted network policy, Python, FFmpeg and the pinned downloader/transcription prerequisites. Ask it to request internet access through the host's normal permission flow when needed. Keep the host's network and isolation controls enabled.
3. Ask for a metadata-only readiness report with `state`, `missing`, `networkPolicy`, `tools`, `requestedModel` and `reportedModel`. Use `unknown` for settings the host cannot verify. Do not include tokens, cookies, private paths or raw source content. This report describes the host; it is not a VibeScroll processing receipt.
4. For exact video requests, review **Allow exact video analysis requests in my Work Cloud chat** once in Connections when it is available. Then ask VibeScroll in the prepared task to analyze your saved post, supplying its VibeScroll link. This option needs no further app approval for each request. If it is unavailable, the separate diagnostic route still requires opening the post, approving the exact connection/source/settings and copying its generated instructions.
5. Keep that task open while it claims the approval, acquires the permitted source and returns cited analysis through the VibeScroll plugin. The video deadline is fifteen minutes, including its active lease. The task must stop on missing access or unsupported media rather than invent evidence or spend API credits.
6. Refresh the existing post after completion. Inspect its coverage and citations. A queued approval or a message in chat is not a saved result. Refreshing the page can recover instructions while that approval is still unclaimed and current.

The first environment preparation can download a model and take longer than a warm run. Reuse verified cached prerequisites where supported; a replacement Cloud environment may need setup again. Source access, speech quality, sampled image coverage, provider retention and subscription limits still apply. This manual diagnostic request does not configure an automatic monitor. A missing plugin permission requires the supported reconnection/consent flow, never a copied token.

## Work Cloud says a private library is required

An older workspace can still use team access even if it is named Personal workspace. The experimental Cloud route also admits an eligible original creator who still owns the workspace alone, with no active invitations. It checks that state without moving or copying posts. Do not upgrade or move a library merely because it has an old team label if Cloud setup is already available.

If the app specifically offers an upgrade, choose **Review private-library setup**, then **Review private-library upgrade** in Team settings. This review starts no analysis.

If you are the original creator and only member, with no active invitations or another private library, you can review the private-only acknowledgement and choose **Make this library private**. Sign in again if requested. Existing posts, projects and links stay in place. Invitations and ownership transfer are unavailable in a private library; use a separate team workspace for collaboration.

A refusal leaves the workspace unchanged. Follow the displayed reason, or choose an existing separate private library from Your workspaces. Making a library private does not connect a processing account or grant execution. Review the assistant connection and approve the exact post afterward. Experimental Cloud availability and successful video execution remain separate.
