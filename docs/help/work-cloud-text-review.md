# Set up automatic Cloud analysis

Own ChatGPT Cloud analysis needs an eligible Cloud host, your connected VibeScroll app and one prepared native saved-link task. The current operator pilot is limited; a paused task does not process another link. A connected MCP app alone does not prove the task is Monitoring.

## One-time setup

1. Open **Connections**, choose **My own Cloud Work**, then **Continue**. Keep your existing VibeScroll MCP connection. Standard access covers your library and confirmed projects within your actual account permissions. Routine setup uses your normal sign-in session.
2. Open **Finish or resume ChatGPT setup**. Copy its message into one ChatGPT Work chat with Cloud and VibeScroll selected. Let readiness finish and wait for the native task to show **Monitoring**. Copying the message alone does not complete setup.
3. Save a permitted Reel or TikTok in VibeScroll, or ask VibeScroll to save its link in a ChatGPT chat where the app is available. Cloud selection already means automatic analysis. Use **Save only** when you want no new processing.
4. Open the returned post link for progress, transcript, sampled images and cited insights. A compatible existing catalog result is reused without another video analysis. The task also reports its outcome in its own chat; VibeScroll cannot insert an unsolicited result into every chat where a link was sent.
5. Return to **Connections** to resume a paused task or complete a missing step. If settings genuinely change, use the setup message for the current grant version. Do not recreate the MCP app or repeat source review for every normal save.

Eligible neutral results can be retained in the shared catalog under the current service policy. Personal notes, repository context and project proposals stay private. Existing private-only results are not automatically published. Default result retention is **until deleted**; worker leases, raw downloads and authentication expire separately. See [Processing, costs and recovery](/help/processing-and-recovery) for the task-location guide.

The sending chat needs no downloader or video runtime. Native Events deliver the saved-link intent to your prepared Cloud Work task. If setup is unavailable, the link stays saved with a setup shortcut. Existing results and uncertain attempts are preserved. No paid fallback runs. Subscription limits, refresh-token expiry or revocation can still require attention; this is not a promise of permanent authentication. For a previously save-only pristine video, **Analyze using Cloud defaults** requests the configured route. **Advanced: manual Cloud handoff** is for deliberate diagnostics.

## Before you start

Use your private library or an eligible team that you created and still own alone, a source you may process and the intended official Work Cloud connection. The team must have no active invitations. Its connection permissions are reviewed separately; posts stay in their existing library. GitHub, Docker Desktop and a paired computer are not required by this handoff. Your host's subscription and resource limits still apply. A model selection is a request; VibeScroll cannot attest the host's actual model, resource controls or usage.

The connection needs **Read separately approved text or public video links and return private analysis**, `analysis:execute`, in both OAuth and the app's current grant. Existing read, save and local-request permissions do not include execution. Assistant preferences use your current signed-in session in the updated setup. An expired session needs sign-in; credentials and separately sensitive approvals retain their own checks. Never paste credentials, bearer tokens or private configuration into a task.

## Request a saved video from your Work Cloud chat

This option appears only when the experimental video route is enabled for your account. In Connections, edit the intended connection, select the library scope and both analysis actions, then review **Allow exact video analysis requests in my Work Cloud chat** and save. This permission starts off. Selecting it turns off automatic local processing in the reviewed settings and requires no paired computer.

In a supported Work Cloud chat with VibeScroll connected, ask VibeScroll to analyze the saved post and provide its VibeScroll link. The assistant reads its current status and sends an exact own-subscription request with a model, effort, retention deadline and maximum API spend of US$0. After this setup, there is no additional app approval for each request. The host must prepare supported tools and restricted Internet permission before claiming work.

The experimental limit is six new source requests per hour. Repeating the identical unclaimed request returns the existing job. This manual waiting receipt does not configure a Cloud task. Eligible pilot accounts can separately set up native automatic app saves using [the setup guide](/help/processing-and-recovery). Two private owner Reel tests completed automatically with the chat tab closed. General customer setup and wider platform acceptance remain open. Old team workspaces do not become private because of their names, and this option does not move their posts.

## Analyze an old post again

For a completed Cloud video with retained evidence, open **Analysis versions** on its post page. History loads when you open it.

1. Check Cloud setup first. The same Work task must monitor both new posts and approved reanalysis requests. If you set up an older save-only monitor, update it using **Set up ChatGPT** in Connections. Reuse the existing connection; a supported plugin rescan updates its tools without creating another app or expanding scopes. Wait for the task to confirm Monitoring.
2. Review the current result and retention, then choose **Analyze again** with a model and reasoning effort supported by your own Cloud task. This reuses the saved transcript and screenshots, uses your subscription and spends 0 VibeScroll credits. Keep the current result while the candidate runs.
3. Open **Review version** when the candidate returns. Inspect its claims, quoted evidence and retained screenshots. **Compare with selected version** reports differences; it does not certify that a newer model is better.
4. Choose **Use version** to select the result you prefer. Choose an earlier retained version to roll back. Selection and rollback start no analysis, download or transcription.

Versions reuse one evidence bundle. Reanalysis cannot recover an expired transcript or missing screenshots. An unclaimed request expires safely. A claimed attempt with an unknown outcome needs reconciliation and is not automatically repeated. Source deletion, withdrawn rights and retention still apply to every version.

Project actions currently remain bound to the original analysis for the current extraction. Existing project reviews preserve their original evidence. Select that original analysis before starting another project evaluation. Private version selection publishes nothing to the shared catalog.

## Shared versions and personal notes

Shared Cloud knowledge is awaiting production acceptance. These controls appear only when the reviewed catalog route is enabled for your account and source.

Saving a link with an eligible shared analysis can reuse its transcript, screenshots and insights immediately. This cache hit starts no Cloud task, download or transcription. Current verified catalog access, reuse permission and retention are checked again when you open a result or image.

The post follows the reviewed catalog recommendation unless you select another version. **Follow recommended analysis** returns to that default. Your personal notes stay with the exact version you reviewed and return when you select it again. An upgrade does not move an old correction onto a different claim.

For an existing compatible private version, **Contribute this version to shared knowledge** previews the exact transcript, screenshots, insights and retention period. Review and authorize that separate contribution only if you want it shared. Personal deletion keeps the independently authorized catalog copy; **Withdraw contribution** removes your contribution's authority. After deleting a personal post, find its receipt in **Privacy > Manage shared contributions**. Account deletion withdraws its remaining contribution authority. A shared recommendation still needs a separate evidence review. Private notes, projects and Cloud task credentials are excluded.

Existing private-only results are not shared automatically. There is no extra connection or OAuth app to create for these version controls. A missing shared control does not mean your existing private analysis or connection is broken.

If this option is absent, use the separately approved diagnostic handoff below when available. Do not disconnect an existing connection, delete posts or switch to paid credits to work around unavailable access.

## Review one diagnostic handoff

1. Open the saved source and expand **Advanced: manual Cloud handoff**. Look for **Experimental Work Cloud text** or **Experimental Work Cloud video**. An absent control means that route is unavailable.
2. Select **Review Work Cloud text** or **Review Work Cloud video**, then choose the intended connection. Review the requested model and effort against the options in your official host. Choose the model explicitly if its Default setting can route to another model.
3. Preview the exact source and connection. For video, review the private result's evidence-retention deadline. The current experimental maximum is thirty days. Raw provider files have a separate cleanup target; VibeScroll cannot verify their deletion or erase provider chat history.
4. Approve your own subscription with maximum API spend **US$0**. This grants no paid fallback, project evaluation or catalog publication.
5. Copy the queued instructions into the supported Work Cloud chat and explicitly invoke VibeScroll. The host creates one unique correlation UUID as `taskId` and calls `work_cloud_claim`. This identifier links the attempt's messages; it is not an official provider identity or proof of execution. Do not reuse another attempt's identifier or token.

The host receives its lease token once and reads only the approved input and policy. Text execution keeps its existing three-minute deadline and forty-second lease. Video execution has a fifteen-minute deadline and a three-minute lease. Send heartbeats between bounded steps, including setup, acquisition, speech recognition and final analysis. A single step must fit within the remaining lease; a heartbeat never extends the hard deadline. These are app-access limits, not proof that the host stops execution.

## Video evidence and setup time

The current caption-first package targets one permitted Instagram or TikTok video. Other platforms require their separately verified route. It acquires the actual source in the user's Cloud environment, reuses usable captions or transcribes speech, and inspects timestamped samples. It does not claim every frame was reviewed. Photos, mixed posts and carousels need their separately supported route.

The first run may need verified downloader and speech-model preparation. Reuse verified cached tools in the same supported environment when available. Do not promise a warm cache in a new task. Keep setup and analysis times separate. Stop when source access, current network enforcement, isolation, requested settings or resource limits cannot be established; do not substitute a caption summary or paid service.

The host binds its observations with `work_cloud_prepare` and uploads the required real sampled JPEGs before submitting final cited analysis through `work_cloud_complete`. VibeScroll checks the source, revision, image hashes and citation bindings. These remain authenticated client reports, not independent proof that a model inspected the bytes. Retained sampled images can appear on the private post. Raw source media has a separate provider-local cleanup target.

## Read the result or recover

Open or bookmark the same post page to inspect the private result and citations. Library also links to it. The manual supplied-text diagnostic does not contribute to the catalog. Normal automatic video results can be eligible for neutral shared reuse under the current service policy. Supplied-text citations do not prove that anyone watched a linked video or verified its claims.

**Revoke this request's app access** prevents further input and result return. Stop the host task too. VibeScroll cannot confirm provider cancellation or restore consumed subscription allowance.

A lost claim, expired execution or uncertain completion is not automatically retried. Replacing source input does not remove that uncertainty or authorize another executor. Reconciliation with the real host remains necessary; do not delete and resubmit as a retry workaround. Privacy deletion remains available, but app deletion does not erase provider-retained task history.

Private owner automatic Reel results have passed with real returned images and matching displayed transcript text. Independent customer setup, manually certified speech accuracy and provider erasure remain unverified. See [Processing, costs and recovery](/help/processing-and-recovery) for setup, the existing paired route and explicitly funded alternatives.

## Confidence and rejected returns

When cited observations contain uncertainty, the Cloud adapter reduces affected support labels to uncertain. This preserves useful results without overstating transcription or sampled evidence.

An operator can prepare an exact retained-result recovery for a fresh owner review. This allows the original task to return only the reviewed result during a fixed short window. It starts no processing and does not verify provider usage. Keep the existing post and Cloud task while investigating a rejected return.
