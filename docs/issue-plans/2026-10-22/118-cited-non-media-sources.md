Status: draft for owner review. [Original issue](https://github.com/StefanDG1/vibescroll/issues/118). Baseline and common checks are in the [review index](README.md).

October 23 owner update: release GitHub first and Reddit later. [ADR 117](../../adr/117-github-first-and-complete-own-subscription-workflows.md) and the [completion plan](../../launch-plan/2026-10-23/README.md) supersede the joint-release condition below. Preserve all independent Reddit permission, dedicated access, currentness and retention/deletion requirements. The October 22 paragraph remains historical.

## Outcome

A user can save a public GitHub repository or Reddit discussion as a private knowledge source, inspect exactly which text was retrieved or supplied, and approve extraction. Every resulting idea retains file/excerpt or comment citations. Project evaluation remains an explicit choice against current selected projects. Saving a source never grants repository write access or permission to spend.

Owner decision, October 22: ship the GitHub and Reddit direct adapters together. Build and review them in separate change sets if useful, but do not release GitHub-only support. Start with the Reddit provider-access spike because it can block the combined release. Linked supplied text remains recovery for unavailable content, not a substitute for the required direct Reddit adapter. Keep an announcement and its repository as separate sources with an explicit relationship, rather than counting them as independent confirmation.

## Research update and proposed refinements

Reviewed October 22 before implementation. These refinements are recommendations for discussion, not new owner decisions.

The current [Reddit developer-access guidance](https://support.reddithelp.com/hc/en-us/articles/14945211791892-Developer-Platform-Accessing-Reddit-Data) says commercial use needs permission and a contract. Its [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy) requires explicit API-access approval. This makes the access spike a provider dependency, not just an experiment to find a working endpoint. No VibeScroll approval, pricing or permitted processing scope was established by this review.

Before live Reddit retrieval, record whether VibeScroll already has the applicable approval. If absent, prepare a commercial request describing selected-thread retrieval, selected model-provider processing for summaries, private storage, citations/exports, deletion and expected bounded volume. Request written clarification of these workloads and any fees. Model training and inference are different uses; do not claim permission for inference from a statement about training. The owner has not authorized submitting a Reddit request or agreeing to fees in this task.

GitHub's [rate-limit documentation](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api?apiVersion=latest) gives unauthenticated requests a 60-request hourly limit associated with the originating IP. A 30-request source ceiling therefore cannot be treated as independent capacity for every hosted user. Add a service-level queue, bounded fairness and rate-limit-aware scheduling, and verify a separate appropriately scoped public-read authentication option before broad release. Do not reuse destination installation credentials or request new destination permissions. Use existing response headers and validated provider retry deadlines; no background polling loop or automatic billable-analysis retry.

Suggested product improvements:

- Start GitHub selection with an editable README/license/docs preset and one confirmation. This preserves explicit file selection while avoiding a raw repository-tree task for every user. Additional source files remain opt-in.
- Show Reddit coverage as the post plus actual retrieved comment count, sample method, omitted branches and observation time. Include parent context for replies. Evaluate sampling on a thread where important disagreement is outside the highest-scoring comments; do not present the sample as community consensus.
- Offer a simple related-sources link when a user saves both an announcement and its repository. Preserve separate revisions/citations and recognize repeated claims before creating repeated project drafts. Reuse existing source relationships if sufficient; a new generalized grouping system is unnecessary for this issue.
- Make refresh an explicit revision preview: identify changed files/comments before another quoted analysis. Provider-required removal handling is a separate retention operation, not an automatic new analysis.

Resolve retention before schema design is considered complete. Immutable provenance must not mean permanent retention of provider-deleted material. The approved provider rules determine removal of cached excerpts and dependent summaries. Retain only permitted non-content audit/tombstone metadata; prevent restores and late worker results from resurrecting removed content. Confirm the agreement permits planned external exports, and describe which already-published GitHub artifacts cannot be silently recalled.

Additional acceptance: two workspaces sharing a service IP respect one provider budget without content leakage; sampling preserves parent context and reports omissions; removal reaches summaries and private exports; restore and stale completion cannot resurrect removed text. Preset selection, source relationships and revision preview remain proposed refinements until reviewed.

## 118-A: define the source and evidence contracts

1. Add source type values for media, GitHub repository, Reddit thread and supplied text, separate from capture method. Existing records resolve through a compatibility reader; do not backfill by visiting stored links.
2. Specify an immutable source revision containing canonical identity, fetched/supplied time, adapter version, content hash, rights basis, availability and coverage/omissions. Keep retrieval status separate from analysis status. Suggested retrieval states are saved, fetching, ready, partial, needs supplied text, unavailable and rate limited.
3. Define typed evidence records for GitHub file excerpts and Reddit posts/comments. GitHub references include stable repository identity, commit SHA, path, line bounds, excerpt hash and canonical blob link. Reddit references include post/comment ID, parent ID, permalink, role and available creation/edit times. Supplied text references retain original URL plus exact supplied excerpt/offsets and identify that no provider fetch verified it.
4. Keep the existing model-facing evidence ID where practical, backed by a server-owned typed evidence registry. A model can cite only IDs from the current source revision. Validate every reference on commit; the model cannot invent a file, line, comment or provider URL.
5. Version serialized insight/output contracts and readers together. Preserve existing media artifacts and legacy assistant clients. Decide whether the current schema converter can express the needed union; extend and test it deliberately if required. Null timestamps alone are insufficient provenance.
6. Use workspace-scoped canonical identity for source deduplication and immutable revision/content hash for processing reuse. A new repository commit is a new revision, not a duplicate of an older analysis. Explicit refresh preserves history and invalidates dependent stale approvals. Never share content caches across tenants.

Proposed initial retrieval limits are 20 explicitly selected GitHub text files, 64 KiB per file, 512 KiB aggregate retrieval, 30 provider requests and a 60-second deadline. Build a smaller extraction input within the existing 60,000-character text ceiling and show what was omitted. For Reddit, propose one original post, up to 50 comments, reply depth three, 256 KiB aggregate text, ten requests and the same deadline. These are reviewable engineering defaults; lower existing provider/operator caps win. No automatic pagination beyond the displayed limit.

Acceptance for this change set: media records still decode; hostile URL/path fixtures fail closed; typed citations round-trip through insight, private draft, export and assistant boundaries without fabricated timestamps.

## 118-B: public GitHub acquisition and complete pipeline

1. Accept an exact HTTPS `github.com/{owner}/{repo}` URL. Strip harmless tracking/fragment data deliberately; reject credentials, nondefault ports, encoded separators, dot paths, lookalike hosts and arbitrary nested URLs. Do not infer a destination project from this source.
2. Resolve public repository identity and a concrete commit through fixed read-only API endpoints. Show the pinned revision, README/license candidates and bounded file choices before content retrieval. Fetch only the selected regular text blobs at that commit. Exclude secrets, binaries, symlinks, submodules, LFS targets and oversized files. Do not use clone, archives, installers, package scripts or third-party download URLs.
3. Use a dedicated public-read transport without destination installation tokens. Enforce actual streamed bytes, request/timeout limits, rate-limit responses and expected response shapes. Revalidate every redirect and resolved address, or reject redirects entirely where the API contract permits. Handle renamed, deleted and newly private repositories explicitly.
4. Save sanitized immutable evidence, then route through the existing bounded extraction and topic pipeline after a current quote/approval or a newly reviewed compatible intake preference. Reserve inference separately from acquisition. Do not reserve audiovisual/transcription compute for text. Keep cancellation, lease/generation, uncertain-settlement and idempotency rules.
5. Feed current selected-project evaluation only after explicit selection and authorization. Preserve useful, no_fit, already_implemented, deferred, unsupported and needs-context results. Treat source README/AGENTS content as quoted data, never agent instructions.
6. Thread new evidence through source detail, topic summaries, private suggestions, plan/issue exports, deletion, correction, source grants and team grants. No raw repository source text becomes exposed through an assistant interface that currently allows only clipped ideas. Source deletion/revocation must reject in-flight commits and stale derived citations.

The [GitHub contents reference](https://docs.github.com/en/rest/repos/contents) supports reading public resources without authentication and selecting a ref. It also documents symlink/submodule behavior and response-size differences. Application limits must be stricter than provider maxima.

Acceptance: an explicitly selected WTFM README/license/docs set yields supported claims with commit/file/excerpt citations. A repository URL creates no destination repository record, installation grant, write token or executable task.

## 118-C: direct Reddit access and supplied-text recovery

1. Check the current Reddit API/access contract for this commercial use and record permitted authentication, retention/deletion, attribution and quotas. The general Devvit API index does not establish permission for an external VibeScroll fetcher. Do not infer permission from a working `.json` URL or use browser scraping to bypass access restrictions.
2. Canonicalize supported full permalinks. Resolve share URLs only through a bounded host/path allowlist, without forwarding credentials, with address checks on every hop. If a short-link form cannot be verified safely, request its canonical permalink instead.
3. When direct access is permitted, fetch the post and a deterministic comment sample, preserving reply relationships, OP versus other-user attribution, deleted/removed markers, ordering and coverage. Declare the sample method and include available ancestor context for each selected reply within the same budget. Record omitted branches rather than inventing complete-thread coverage. Votes and repetition do not prove a claim. Comment omission or deletion cannot become fabricated evidence.
4. Otherwise return `needs_supplied_text` and open the linked text form. Let the user paste post and selected comments with attribution. Label missing context and user-supplied provenance. Do not report a successful Reddit acquisition or a complete-thread summary.
5. Store a related-source link to the GitHub announcement only when explicitly chosen or confirmed. Extraction can identify disagreement, but cannot convert two copies of one announcement into independent corroboration.
6. Update web and MCP supported-source descriptions only when the corresponding flow works. For new types, initially save metadata and require explicit processing review. Existing assistant analysis defaults must not silently gain new acquisition capabilities. Any preference expansion receives a versioned review.

Acceptance: permitted direct retrieval of an accessible discussion produces separately attributed OP/comment evidence. If the issue's exact example is inaccessible, record that result honestly and verify direct retrieval against another permitted accessible thread; do not claim the original example passed. Also verify the supplied-text recovery path for blocked/deleted/rate-limited sources. Both paths support correction, deletion and current evidence checks. Supplied-text-only support does not satisfy the owner's combined direct-adapter release decision.

Add new source URL, adapter, citation and Convex integration suites. Mock external responses; never execute fixture repositories.

Run targeted Vitest suites through `pnpm exec vitest run <inspected-or-new-test-paths>`, then the shared repository checks. Walk through save, selection, quote, evidence, evaluation and export at 320/390/1440 widths with keyboard access. Separately record real read-only adapter acceptance on permitted examples. Model-consuming acceptance needs the selected funding approval; fixture tests do not establish it.

Release compatible contracts/readers first without exposing the new source types. Exercise both direct adapters in a test workspace, then expose both in one reviewed release only after each complete evidence-to-export test passes and Reddit access is verified. A blocked Reddit integration holds the combined feature release; it does not authorize a GitHub-only release. Provider outages after launch have honest per-source failure/recovery states. On release rollback, stop new acquisitions for both new types, fence pending jobs, preserve readable source history and holds, and return new-source intake to an explicit unavailable/supplied-text state. Do not downgrade away data written in the new evidence format.
