## Target experience

A person connects their own eligible ChatGPT account through the official host, connects VibeScroll, sends a supported public post link or follows a creator, and receives a cited general analysis in VibeScroll. OpenAI's user-owned cloud environment performs permitted acquisition, preparation, transcription and model reasoning. No VibeScroll-paid inference or preparation is silently substituted. Eligible generic results become part of a free public reusable library under a disclosed publication and licensing contract. Personal reanalysis, goals, prompts, skills, repository evaluations, proposals and plans remain private.

This target is not live. The initial personal demo task failed before shell execution. The owner then supplied a new saved Instagram Reel. One MCP profile read and two guarded thirty-item production listings resolved that exact source and verified zero insights and no personal analysis job. A separate personal real-post Cloud task has a working Linux shell, Python 3.12.14 and FFmpeg 7.1.5. Its current restricted network enforcement has alternated between unknown and enforced across observed revisions, without configuration changes by this run. The pinned downloader passed exact size and SHA256 verification. The first acquisition invocation stopped at an unavailable executor DNS check before reaching Instagram. A proxy-native second invocation reached metadata but failed CDN trust validation. A separately bounded third invocation using the pinned downloader's documented system-CA option retained TLS/hostname checks and succeeded. It acquired a 46.901451-second, 3,667,745-byte clip, ran verified offline CPU/int8 ASR over actual audio and natively inspected eight frames at 0/6/12/18/24/30/36/42 seconds. Cited analysis was completed before the work deadline. This is one personal audio-plus-sampled-visual proof, not complete-frame inspection or a production adapter. These personal tests are independent of customer orchestration, production write-back and public release.

The owner prioritizes this route over an awake local computer. Local processing and managed-credit processing can be postponed from the immediate launch path **only after** the Cloud route passes C0-C3 and provides a usable recovery path. Preserve existing tested behavior and stored work. Do not remove those implementations or describe their remaining acceptance as passed. Claude Code/Gemini subscriptions and video-style copying are future roadmap items.

## What the latest instruction changes

- Prefer official user-owned Codex Cloud, including media preparation and inference, rather than merely moving the existing local controller to a VibeScroll server.
- Process links. An uploaded-file example, caption summary, successful webhook or task-creation response cannot satisfy real link-to-cited-insight acceptance.
- Use a fixed versioned neutral extraction policy for the shared base. New eligible generic processing has a disclosed public contribution requirement, with no per-result private toggle. This is not permission to migrate legacy/private data or waive removal rights.
- Keep private customization separate. A user can rerun with their own goals, prompt additions or approved skills without contaminating the canonical generic result or spending other subscribers' allowance.
- Coordinate subscribers to avoid duplicate compatible analysis. Randomized contributor selection and failover are desired, but account-specific consent, provider permission, bounded consumption and confirmed attempt ownership are prerequisites.
- Make the public knowledge benefit a central, testable marketing angle. Do not publish claims of universal source access, instant response, zero operating cost, achieved savings or an existing community.
- Retain daily public TikTok/Instagram following without requiring creator cooperation, video/image/photo/mixed-carousel formats, future posts by default and optional latest ten. Supplier/collection/redistribution permission remains independently necessary.

## Capability findings and decision gates

[MCP Events](https://developers.openai.com/plugins/build/mcp-events) is a candidate wake-up transport for a user-authorized hosted Work chat. It is not the decoder or an unrestricted Cloud task API. A signed delivery acknowledgement does not establish processing. Prove separately that the supported Work chat can execute this media workflow in a usable Codex Cloud environment; documentation of Events alone does not establish that bridge.

[Codex Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments) support remote work while the computer sleeps. Current setup documentation selects GitHub repositories. A no-GitHub setup must be proved; do not silently make optional project GitHub mandatory or promise an available repository-free Cloud environment. Computer/browser use is currently listed as unsupported, so browser-dependent social acquisition cannot be assumed.

The installed experimental cloud CLI is authenticated, but its environment inventory differs from the new web UI. No undocumented endpoint, copied browser credential or guessed environment ID is acceptable. The existing `subscriptionTrials` codex_cloud text comparison remains a useful manual investigation/recovery path, not a production orchestration system.

[App-server documentation](https://learn.chatgpt.com/docs/app-server) disallows its managed authentication for commercial/hosted services. The separate [Sign in with ChatGPT plan-usage partner route](https://developers.openai.com/siwc/token-sharing-open-source) has its own eligibility process. A personal task does not approve a product that orchestrates all customers' subscriptions. [Managed Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview) is separately billed and is not a subscription substitute.

The proposed subscriber pool is not yet provider-approved. The [account and usage restrictions](https://openai.com/policies/eu-terms-of-use/) require review. Do not implement cross-account routing to bypass exhausted limits or share credentials. Each prospective contributor must independently authorize the creator/workload, their own host/account, period, model, concurrency and allowance ceiling. Quota rejection pauses that contributor; it cannot automatically become permission to shift an uncertain or rate-limited attempt elsewhere.

Public distribution has another gate. The [sharing policy](https://openai.com/policies/sharing-publication-policy/) specifies manual generation review for its sharing scenarios. As a product release control, quarantine new public candidates while the exact library use case and applicable review process are resolved. Do not present that control as a finding that every public library legally requires manual review or that a special agreement is the only permitted path. Today's seven reviewed insights retain their exact-edition approval. Generic wording alone does not establish redistribution rights or remove private/sensitive data.

## Required pipeline

There are two different triggers. A pasted link already supplies a source intent, so its event can wake authorized processing. Following a creator requires discovery first. MCP Events cannot detect a new Instagram/TikTok post by itself. Reuse the existing daily watch coordinator and permitted discovery transport, or prove a separately authorized official-host scheduled discovery task that reports into that coordinator. If every discovery executor is unavailable, show the last completed check and an incomplete state; do not claim no new posts. Discovery/scheduling, storage, metadata delivery and moderation still consume resources even when media and inference execute entirely in the user's Cloud environment.

The contributor selection contract may cover discovery and processing as distinct workloads with separate scope, deadlines and ceilings. Avoid a circular design in which the host waits for an event that only that same unscheduled host could create. No recurring task or supplier is activated by this plan.

1. Resolve a permitted link to stable provider/creator/post/ordered-child identity and immutable content revision. Recheck all redirects, allowed domains and access rights; unavailable access stays unavailable.
2. Check compatible approved public generic analysis first. A URL alone is insufficient. Compare actual content identity, language, policy/schema/tool versions, inspected coverage, reuse rights and moderation/deletion state.
3. On a miss, join one existing source intent. Keep private recipients separate from its executing contributor. Do not launch one inference per follower.
4. Select an eligible authorized contributor only under the approved provider contract. Randomize within a fair bounded candidate set after capability, cooldown, concurrency and per-period ceilings. Record selection without exposing contributor identity to public readers.
5. Wake the official Cloud host through the verified transport. The host claims a short-lived scoped input lease. An event body carries minimal identifiers, never task instructions from untrusted source content or account credentials.
6. Acquire and prepare media inside the user's Cloud environment. For unattended release, require supported external enforcement of network, duration, asset, byte, CPU and account-usage limits before dispatch. Prompt instructions alone do not establish a hard bound. Prove that cancellation, expiry and lease loss stop actual execution; rejecting a late result alone is insufficient. If the host cannot provide these controls, keep unattended orchestration and contributor handoff gated. No cookie extraction, private-post bypass, CAPTCHA bypass or undocumented API.
7. Transcribe actual supported speech, inspect actual ordered images and time-indexed sampled frames, retain original transcript separately from corrections, and validate source references. Emit explicit unavailable, partial or unknown coverage where appropriate.
8. Submit a strictly validated versioned result through a scoped completion tool. Verify contributor/task/source/policy/lease bindings, input/frame hashes, actual observations, citations, usage uncertainty and current rights. A model's self-report alone is not provider-attested execution.
9. Persist the compatible neutral base in the existing artifact family, apply public release review/moderation/licensing rules, then attach private imports and digests to eligible subscribers. Never embed private personalization in the public base.
10. Retry only after confirmed non-dispatch, terminal failure or reconciled cancellation. Unknown completion retains its attempt and uncertainty hold. Moving to another user requires distinct consent and provider permission; never race active attempts or manufacture zero-cost retries.

## Public contribution and customization rules

The default shared mode applies only to newly submitted, eligible public-source generic work after clear onboarding disclosure and a valid rights/publication contract. There is no per-result privacy opt-out within that mode. A person may decline to start it, stop future contribution or disconnect their own processing. Statutory deletion, correction, reporting, safety and rights-based takedown are not removable product options.

Do not publish private uploads, DMs, paywalled material, private repositories, personal notes, private/sensitive/unauthorized personal data or legacy analyses merely because the output was written in general language. Keep unreviewed output quarantined under the release control above. A neutral result retains permitted public creator/source provenance and distinguishes source claim from model interpretation. Do not redistribute raw videos/transcripts/frames or attach a blanket open-source license to third-party media.

Document provider-specific retention and deletion for source bytes, transcripts, frames, leases/results, task/log history and environment files. Test cleanup, disconnect and revocation separately from VibeScroll removal and restore. Deleting an app association cannot be reported as deleting an independently retained official Cloud task. Public correction/removal must propagate across eligible derivatives without erasing private material outside the disclosed contract.

Choose and review a separate public insight/data license before free bulk export/reuse. The software MIT license does not automatically license source content or all model output. Contributor agreement, independent retention basis, removal propagation and permitted attribution must be specified. Law/provider checks remain gates, not claims of legal approval.

Private advanced settings can add user instructions, goals or approved skills for a separate reanalysis. Verify each skill's source, exact version/hash and supported Cloud destination; a local installation or recommendation does not establish Cloud availability. Label unavailable or unknown installations honestly. Installation, tool execution and egress need their own bounded authority. The neutral base excludes users' private/custom skills; a fixed reviewed processing skill belongs to its versioned policy/toolchain. Its identity includes input revision, private prompt/context/skill digests and model settings; it never changes the neutral public cache key. Preserve private custom output, per-user corrections and editable project proposals/plans. Security constraints and tool authority remain outside user-editable prompts.
