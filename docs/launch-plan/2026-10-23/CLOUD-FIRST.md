## Capability findings and decision gates

[MCP Events](https://developers.openai.com/plugins/build/mcp-events) is a candidate wake-up transport for a user-authorized hosted Work chat. It is not the decoder or an unrestricted Cloud task API. A signed delivery acknowledgement does not establish processing. Prove separately that the supported Work chat can execute this media workflow in a usable Codex Cloud environment; documentation of Events alone does not establish that bridge.

[Codex Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments) support remote work while the computer sleeps. Current setup documentation selects GitHub repositories. A no-GitHub setup must be proved; do not silently make optional project GitHub mandatory or promise an available repository-free Cloud environment. Computer/browser use is currently listed as unsupported, so browser-dependent social acquisition cannot be assumed.

The installed experimental cloud CLI is authenticated, but its environment inventory differs from the new web UI. No undocumented endpoint, copied browser credential or guessed environment ID is acceptable. The existing `subscriptionTrials` codex_cloud text comparison remains a useful manual investigation/recovery path, not a production orchestration system.

[App-server documentation](https://learn.chatgpt.com/docs/app-server) disallows its managed authentication for commercial/hosted services. The separate [Sign in with ChatGPT plan-usage partner route](https://developers.openai.com/siwc/token-sharing-open-source) has its own eligibility process. A personal task does not approve a product that orchestrates all customers' subscriptions. [Managed Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview) is separately billed and is not a subscription substitute.

The proposed subscriber pool is not yet provider-approved. The [account and usage restrictions](https://openai.com/policies/eu-terms-of-use/) require review. Do not implement cross-account routing to bypass exhausted limits or share credentials. Each prospective contributor must independently authorize the creator/workload, their own host/account, period, model, concurrency and allowance ceiling. Quota rejection pauses that contributor; it cannot automatically become permission to shift an uncertain or rate-limited attempt elsewhere.

Distribution to other catalog subscribers has another gate, as does any separately approved public demo. The [sharing policy](https://openai.com/policies/sharing-publication-policy/) specifies manual generation review for its sharing scenarios. As a product release control, quarantine new shared candidates while the exact paid-catalog use case and applicable review process are resolved. Do not present that control as a finding that every public library legally requires manual review or that a special agreement is the only permitted path. ## Required pipeline

There are two different triggers. A pasted link already supplies a source intent, so its event can wake authorized processing. Following a creator requires discovery first. MCP Events cannot detect a new Instagram/TikTok post by itself. Reuse the existing daily watch coordinator and permitted discovery transport, or prove a separately authorized official-host scheduled discovery task that reports into that coordinator. If every discovery executor is unavailable, show the last completed check and an incomplete state; do not claim no new posts. Discovery/scheduling, storage, metadata delivery and moderation still consume resources even when media and inference execute entirely in the user's Cloud environment.

The contributor selection contract may cover discovery and processing as distinct workloads with separate scope, deadlines and ceilings. Avoid a circular design in which the host waits for an event that only that same unscheduled host could create. No recurring task or supplier is activated by this plan.

1. Resolve a permitted link to stable provider/creator/post/ordered-child identity and immutable content revision. Recheck all redirects, allowed domains and access rights; unavailable access stays unavailable.
2. Check compatible approved catalog analysis under current entitlement and origin authority first. A free account cannot obtain another contributor's cached result merely by submitting its URL. A URL alone is insufficient. Compare actual content identity, language, policy/schema/tool versions, inspected coverage, reuse rights and moderation/deletion state.
3. On a miss, join one existing source intent. Keep private recipients separate from its executing contributor. Do not launch one inference per follower.
4. Select an eligible authorized contributor only under the approved provider contract. Randomize within a fair bounded candidate set after capability, cooldown, concurrency and per-period ceilings. Record selection without exposing contributor identity to catalog readers.
5. Wake the official Cloud host through the verified transport. The host claims a short-lived scoped input lease. An event body carries minimal identifiers, never task instructions from untrusted source content or account credentials.
6. Acquire and prepare media inside the user's Cloud environment. For unattended release, require supported external enforcement of network, duration, asset, byte, CPU and account-usage limits before dispatch. Prompt instructions alone do not establish a hard bound. Prove that cancellation, expiry and lease loss stop actual execution; rejecting a late result alone is insufficient. If the host cannot provide these controls, keep unattended orchestration and contributor handoff gated. No cookie extraction, private-post bypass, CAPTCHA bypass or undocumented API.
7. Transcribe actual supported speech, inspect actual ordered images and time-indexed sampled frames, retain original transcript separately from corrections, and validate source references. Emit explicit unavailable, partial or unknown coverage where appropriate.
8. Submit a strictly validated versioned result through a scoped completion tool. Verify contributor/task/source/policy/lease bindings, input/frame hashes, actual observations, citations, usage uncertainty and current rights. A model's self-report alone is not provider-attested execution.
9. Persist the compatible neutral base in the existing artifact family, apply contribution/review/moderation/access rules, then attach private imports and digests only under current Pro entitlement or verified own-result authority. Preserve saved copies after cancellation while blocking fresh catalog updates/imports. Never embed private personalization in the shared base.
10. Retry only after confirmed non-dispatch, terminal failure or reconciled cancellation. Unknown completion retains its attempt and uncertainty hold. Moving to another user requires distinct consent and provider permission; never race active attempts or manufacture zero-cost retries.
