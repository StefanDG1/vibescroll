## Cost and request controls

The actors advertise starting rates. These are not whole-job ceilings. A zero-result check, start/minimum charge, event mix, retries, proxy/compute, retained dataset/media, egress, model preparation, inference, reporting lag and cleanup must fit the reviewed reservation. A free tier does not establish permission or a zero worst-case cost. Apify documents per-run `maxTotalChargeUsd`; that is not a whole-account or cross-service ceiling, and a client HTTP timeout does not prove an actor stopped. See the [official run API](https://docs.apify.com/api/v2/actor-run-get) and [official actor runtime contract](https://github.com/apify/actor-code-runtime/blob/master/docs/API.md).

The original ledger retains US$1.6792885298898517, leaving US$0.32071147011014833. The full unknown backend envelope remains held. No supplier check, reference-set run or ongoing watch is currently bounded within that remaining amount. Their live acceptance is pending. The implemented configuration has no selected supplier, price or funded default. A reviewed configuration must independently bind provider, current rights evidence, expiry, unit-named global budget key, full-check ceiling and maximum checks. It cannot spend customer subscription allowance as service money.

## Reference-set protocol

The proposed 20-account set is not completed research. Choose public accounts with a documented lawful basis across both platforms and record the denominator. Include videos, still images, TikTok photos, mixed carousels, pinned/old/new posts, more than one page, changed handles, unavailable/deleted posts, missing dates and partial media. Do not use private account cookies or evade an access restriction.

For each account, compare observed stable creator/post/child IDs, actual publication order, page termination, media order/type and availability against a manually inspected authorized reference. Record omissions and uncertainty. Recheck a bounded subset for revision/removal behavior. Quote discovery, acquisition, preparation, neutral analysis, private evaluation, storage and cleanup separately before starting. The original cap is shared across all attempts and agents.

## Existing-record ownership

The dormant transport uses the documented [actor run start](https://docs.apify.com/api/v2/actors-runs-post), [run status](https://docs.apify.com/api/v2/actor-run-get), [run abort](https://docs.apify.com/api/v2/actor-run-abort-post) and owned-storage deletion APIs. Exact actor/build IDs, memory, time, item and maximum-charge settings must be reviewed before configuration. It permits at most twelve physical supplier requests per check and five serial due watches per dispatcher. Dispatch receipts precede each request. A lost start acknowledgement, unknown cost or unconfirmed cleanup pauses the watch and retains its hold. An invalid watch cannot indefinitely block later healthy watches.

TikTok's documented `profiles` input accepts user IDs, so the adapter sends the resolved stable creator ID, not a mutable handle. Instagram's handle-based transport refuses creator-specific permission scopes because a handle can change owners before collection. It remains unavailable for that narrower scope until a verified immutable-ID route exists. A successful bounded dataset is still marked incomplete creator coverage. Continuing daily incomplete snapshots requires an explicit reviewed policy; unknown billable outcomes always stop. The optional hourly dispatcher is absent unless `CREATOR_DISCOVERY_CRON_ENABLED` is explicitly enabled. This is implemented control logic, not supplier acceptance or new authorization to spend.

Creator watches coordinate discovery by stable platform identity. Private subscriptions, delivery decisions and digest records belong to the existing private workspace owner. They contain no independent inference queue. New source creation goes through the existing capture and canonical identity checks. Analysis remains in the existing source/local-run workflow. Generic analysis belongs in the existing public artifact family with an explicit service origin and managed payer; personal overlays remain separate. Older edition-origin artifacts retain publisher/source currentness and cannot be relabeled as service-owned data.

Versioned ordered-media contracts distinguish still-image evidence from actual video time ranges. Hashes, original child indices, cumulative bytes/minutes, crops and inspected coverage must survive every reader. A complete manifest does not claim every child was visually inspected. Unknown dates or asset limits require review. Future-only delivery uses the server-confirmed follow cutoff; optional latest ten counts posts and quotes their asset/minute totals.

Remaining live evidence: arbitrary-public-creator cohort acceptance, supplier/rights approval, whole-job price bound, measured reference set, isolated multimodal acquisition, both real processing routes, removal/restore behavior, native device review and independent production sessions. Local fixtures cannot close these gates.
