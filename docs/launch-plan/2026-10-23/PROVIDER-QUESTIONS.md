# Provider questions for user-owned Cloud contribution

Mode: reference. Unsent approval brief, October 23, 2026. No provider acceptance is implied. Read [ADR 121](../../adr/121-codex-cloud-first-and-public-neutral-library.md) and [the integrated plan](CLOUD-FIRST.md).

## Proposed product

VibeScroll is a web application with an MCP integration. Each user retains their own official ChatGPT account and OpenAI-hosted execution environment. VibeScroll would never collect or share ChatGPT credentials. Users choose permitted public creators or send permitted post links. The official host would acquire and prepare media, transcribe supported audio, inspect visual evidence and return structured cited general insights through scoped VibeScroll tools.

Compatible eligible generic insights would enter a free public library under a reviewed contribution/license/release policy. Personal prompts, goals, notes, repository context, evaluations, proposals and plans would remain private. VibeScroll would coordinate metadata and reuse; it would not provide a pooled founder subscription or silently pay for model/API work.

## Exact confirmations needed

1. Is this workload permitted in a user-owned official Codex Cloud environment when initiated through a connected third-party MCP integration?
2. Can a supported hosted Work chat receiving MCP Events execute in the selected Codex Cloud environment, remain available after its original turn, and call scoped input/result tools? What cancellation, expiry, batching and quota behavior is guaranteed?
3. Is a user allowed to authorize bounded recurring creator discovery and analysis for their own follows, with general output reused publicly by other interested readers?
4. May VibeScroll select one explicitly consenting eligible subscriber per shared source or daily discovery intent? May it hand off a definitively failed/canceled attempt to another consenting subscriber? What usage, commercial, fairness and limit-circumvention restrictions apply? No handoff after quota rejection or unknown completion is proposed without explicit permission.
5. Which applicable publication review and disclosure requirements govern this public insight-library use case? Can review be performed by the operator or designated reviewers before release? What changes, if any, are required for unattended release?
6. What official scopes and callbacks are available for task dispatch, input leases, actual execution receipts and result return? Does ordinary identity sign-in grant any of these, or is separate partner eligibility required?
7. Is a no-project-GitHub setup supported for a beginner who only wants a Library? Can a maintained public processing environment be installed without granting private repository access?
8. What per-user allowance, network, resource, deadline and concurrency controls can be enforced outside the model before execution? Can cancellation, expiry or lease loss stop the actual running Cloud turn? How are uncertain completion and revoked sessions reconciled without extra paid usage? Result rejection alone does not stop consumption.

9. What retention and deletion controls cover downloaded source bytes, transcripts/frames, task/log history, execution receipts and environment files? What remains with the official provider after disconnect, revocation or removal of the VibeScroll association?

## Separate source-provider questions

TikTok/Instagram collection, media access, creator identity, image/photo/mixed-carousel coverage, retention/deletion and derived-output redistribution require their own verified basis. Creator cooperation is not the requested discovery model. A public URL or a user's saved link alone does not supply every required right. Ask for the permitted transport/workload and limitations rather than replacing this requirement with creator OAuth or an access bypass.

No outreach has been sent. Existing provider interest applications and permissions remain unchanged. Answers must identify the actual workload, actors, deployment, expiry and restrictions before production activation.
