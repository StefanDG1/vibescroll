## How local processing works

The website stores the library and offers controls/results from a phone or computer. An eligible user's paired Windows computer runs that user's approved own-subscription tasks while awake and online. The protected official Codex controller uses their account. VibeScroll does not lend the founder's subscription or silently switch failures to paid API inference.

Supplied text goes through the official account connection and returns structured cited results. Video is hybrid. Approved isolated hosted preparation creates bounded audio and sampled images; local Whisper transcribes supported audio; the official model receives supported text/image evidence. Raw audio/video is not treated as supported model input. Preparation/storage can consume VibeScroll resources, inference uses the provider allowance, and local work uses CPU/electricity. This is not offline inference or zero-cost processing.

The candidate coordinator also handles approved selected-repository evaluations and editable plan drafts. Repository excerpts remain private context. Coding execution and draft PR creation retain separate approvals and isolation. Pairing or generating a plan grants neither. Ordered image/carousel analysis belongs to the new candidate, not the current live release.

The serving revision still launches the older assistant-intake worker through `companion run`. Use a release's matching instructions; do not combine commands across versions or start competing controllers. The updated [computer guide](../../help/connect-your-computer.md) and [operator guide](../../operations/personal-analysis-runner.md) describe the unified candidate explicitly.

### When the computer is needed

Saving, importing selected Saved metadata, browsing, filing and reading available results use the website. New own-subscription inference needs the awake paired worker, matching account/workspace, current source permission, supported model/effort/input, allowance and explicit approval. Sleep/offline leaves work waiting or expiring. Startup is optional and cannot wake hardware.

The supported executor uses Windows, Node 24, a local Docker Desktop Linux engine, pinned official-client image and sufficient disk. Video also needs reviewed media tools/image and the local transcription environment/model. The reviewed project runtime is Node 24.22.1; source setup uses pnpm 12.3.4. ASR checks CPython 3.13, faster-whisper 1.2.1 and exact model files. Complete transitive binary installation trust remains unfinished.

Credentials stay in Windows Credential Manager/protected local storage. Evidence still reaches the authorized provider, and results return to VibeScroll. Renewal/reconnect uses official consent when needed. General customer and computer-free hosted subscription access remain provider-gated; a founder run or paired device cannot establish public eligibility.
