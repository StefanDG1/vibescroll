## Keep the data model small

Define the following contracts before changing handlers. These are logical records; reuse existing compatible tables rather than creating a parallel catalog.

| Record               | Identity and purpose                                                                                              | Storage and access                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Canonical post       | Provider and stable post/video identity; normalized aliases                                                       | A URL is a locator, not proof of unchanged content or reuse rights.                                                                           |
| Source revision      | Immutable content fingerprint, evidence identity, language and revision time                                      | Preserve old revisions when the provider changes the content. Keep private inputs outside the shared catalog.                                 |
| Evidence bundle      | Revision plus downloader, caption/ASR, sampling and schema fingerprints; transcript and frame manifest            | Content-address blobs once within an authorized retention boundary. Keep raw audio/video short-lived.                                         |
| Analysis version     | Immutable output, evidence-bundle reference, recipe, requested/reported settings, output hash and origin          | Extend the existing artifact family. Give every version its own durable ID and human display number. A display number is not a quality score. |
| Analysis attempt     | Finite job/lease, version candidate ID, grant, requester, idempotency key, funding, outcome and usage             | Keep operational retries and failures separate from successful versions. Never reset an unknown attempt to create a replacement.              |
| Selection            | Current approved version for a source revision, language, coverage and reuse policy; selection revision and audit | Use one small pointer with compare-and-set updates. Record previous selections so rollback changes a pointer without inference.               |
| Personal association | Saved post, selected shared artifact, optional pinned version and private overlay                                 | Extend `publicImports` and existing source associations. Do not copy the full catalog result into every user's source row.                    |

Keep immutable output separate from mutable eligibility, safety blocks and selection history. A takedown or required erasure may remove content while retaining a minimal non-content audit record. Version history never overrides deletion or retention requirements.

Separate a source revision's identity from the current execution generation. Bind each new job to its candidate version and exact evidence revision. Keep old citations and image authorization bound to the historical version's evidence, not the latest source job generation. Do not continue to authorize expired evidence through an old version ID.

Represent analysis provenance honestly. Record provider, agent/runtime recipe, prompt hash, schema, requested model/effort, reported model/effort, observability level, timestamps and evaluation policy. Store unknown values as unknown. A user-selected model label is not provider attestation. Private contextual analysis can use shared evidence when permitted, but its output cannot become neutral shared analysis without a separate input-bound contribution contract.

## Cache each expensive stage independently

1. Cache bounded metadata by stable provider identity, retrieval time and freshness policy. Show it before analysis when available. Treat failure to fetch metadata separately from failure of the analysis.
2. Reuse a currently valid evidence bundle for the same source revision. Prefer usable native captions. Run offline ASR only when captions are absent or unusable. Reanalyzing insights alone must not redownload a video or transcribe the same speech.
3. Key an analysis variant by evidence fingerprint, recipe/prompt/schema, supported model configuration, reasoning setting, language and output coverage. Keep source/grant/task IDs out of cross-user compatibility keys. Authenticate and authorize before revealing a hit or a miss.
4. Serve the current eligible selected analysis on an ordinary Save. The caller may request a minimum approved quality tier. Reuse an accepted stronger compatible result when that satisfies the request; do not run a weaker model merely because a different exact configuration was requested.
5. Make explicit Reanalyze bypass only the final analysis cache. Default to reuse of valid evidence. Put full media refresh in a separate advanced action with fresh acquisition bounds. A changed transcript or source content creates a new evidence revision.
6. Coalesce compatible in-flight requests transactionally. Give one eligible producer one finite job. Other users receive an opaque shared pending reference, never the producer's private source, grant, task, funding or logs. A follower does not authorize spending from another user's subscription. If the producer loses authority, reconcile its outcome before admitting fresh work.
7. Use unique operation keys for deliberate repeated analyses. Two retries with the same key return the same attempt; a new explicit request may generate another candidate with the same model recipe. Deduplicate identical outputs by content hash without deleting attempt lineage.

Paginate version lists and comparison metadata with indexed cursors. Home, Library and MCP search return only compact metadata and selection/version IDs. Load the full analysis, transcript or images on demand. Cache neutral server data by version and selection revision, but keep authenticated DTOs and signed media URLs out of public CDN caches. Recheck entitlement, rights, retention and moderation at every read and asset grant. Evict or invalidate on those changes; a stale cache entry grants no access.

Share retained frames and transcript blobs by evidence reference. Do not retain another video/audio copy per model version. Make reference accounting and deletion continuations race-safe. Account deletion removes private data and associations; permitted independently owned neutral artifacts survive only under their valid contribution authority. A canonical rights/privacy takedown blocks all affected versions, imports, search indexes and cached reads. Rollback cannot resurrect erased bytes.

## Select a better result without trusting model names

Validate schema, exact evidence identity, citation existence/times, asset completeness and neutrality before quality comparison. Reject unsupported claims and private-context leakage. Compare transcript faithfulness, visual grounding, missing important points, factual contradictions, distinctness and usefulness against a frozen rubric. Keep confidence and verbosity from acting as quality scores.

Treat model capability and reasoning effort as candidate-generation preferences. Maintain a dated, evaluated configuration registry instead of lexically sorting model names or assuming that higher effort always wins. Keep unknown host settings out of verified capability tiers. Start with reviewed selection for a small test set, including blinded comparison against existing results. Add automatic promotion only after that comparison policy has independent regression evidence.

Use the best approved eligible version as the default. If a candidate loses, preserve it for authorized comparison and keep the incumbent. If no candidate is clearly better, require review. Do not change the global default because an ordinary user presses Use this version. That action pins only their saved-post association. A service selection update checks the expected current selection revision, records its reason and invalidates affected metadata caches. Concurrent stale promotions fail safely.

Keep existing proposals, saved citations and private notes pinned to their original version and insight IDs. Display availability of a newer recommended version. Do not remap a note to a different model's insight merely because their positions or titles look similar. Rollback restores an eligible previous selection and records another selection event. It does not rewrite history, reacquire media, rerun AI or approve coding.

## Execute and release in this order

### V0: freeze contracts and verify migration bounds

Inspect the actual serving schema, relevant table counts/indexes, current grants, entitlement paths, producer contracts and retained assets through bounded reads. Trace the main candidate's existing independent artifact implementation before choosing a schema change. Produce an additive compatible migration/backfill bound, with no full-main five-index rollout as an incidental prerequisite. Do not treat a worktree's tests as production evidence.

Keep valid legacy analysis as a baseline version when first visited or reanalyzed, preserving original provenance and unknown settings. Use a resumable cursor backfill only where necessary. Do not scan or reprocess the whole library on deployment.

Exit when the schema and migration plan explain how existing ready results and their citations remain readable during the first reanalysis.

### V1: make ordinary Cloud processing dependable

Complete cold and warm setup in the task that receives the event. Verify current tools and model bytes rather than depending on a named old directory or historical receipt. Use the published pinned bootstrap before claiming a source job when the approved cache is absent. Diagnose recurrent generated partials with bounded inventories and writer/phase receipts; preserve strict verification. Admit one deterministic cold provision within the reviewed setup limit, with no download or install inside a source lease.

Make setup status reflect actual connection, subscription, expiry/renewal, quota, runtime and last successful execution. Separate a paused or unfunded pilot from a broken MCP connection. Provide the exact one-time setup guide and a targeted repair link for the missing step; do not recommend deleting/recreating an app for a runtime problem. Reuse supported OAuth refresh and native subscription renewal. Never promise authentication forever or resume an exhausted budget silently.

Instrument Save, event receipt, host start, readiness, claim, metadata, acquisition, captions/ASR, frames, model analysis, validation, uploads and final display. Keep acquisition in one bounded inspect/acquire operation and reduce unnecessary host/tool round trips. Report host scheduling separately from measured processing. Aim for a warm 30-to-60-second Reel result within 3 minutes end to end, with cold setup shown separately; this is an engineering target to measure, not a supported provider SLA or a launch claim. Do not present a made-up percentage.

Release runtime/status/recovery improvements after exact CI and a bounded actual Save with the chat closed. Require sequential warm/cold/restarted-task tests before claiming general customer setup works. Record misses and unsupported sources honestly; offer an upload fallback where already supported.

### V2: add private version history and safe force analysis

Add **Reanalyze**, **History**, **Compare** and **Use this version** to the same post page. History stays lazy. Keep the current result visible while a candidate is queued/running/failed. Do not add a boolean that bypasses the old no-overwrite guard. Replace that guard only after writes target a separate candidate and preserve the incumbent. A reanalysis must create a fresh approved attempt; it never reopens an old completed/expired/unknown lease.

Release when an already analysed Reel produces a second version without changing the first, a failed third candidate leaves the selected result intact, and duplicate submissions create one attempt. Start with one owner-selected permitted post after budget reconciliation. Leave the reserved post and unknown attempts alone.

### V3: add comparison, promotion and rollback

Prove that selection and rollback use existing data with zero new inference, media acquisition or processing charges. Keep historical citations stable and mark expired evidence unavailable. Keep notes, repository context, personal recommendations and credentials private. Existing private-only results stay private unless their contributor authorizes the compatible contribution path.

Verify revoked/expired access, subscription renewal, account isolation and cleanup. ## Make MCP cover the useful actions

Keep tools aligned with user goals, without requiring a custom widget:

| User intent                  | Existing surface to extend                      | Required behavior                                                                                                               |
| ---------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Save or analyse this link    | `save_link`, `request_analysis`                 | Ordinary reuse or one authorized new job; explicit new-version intent for reanalysis.                                           |
| Show progress                | `get_job_status`                                | Current attempt/version IDs, stage and safe diagnostic; retain the incumbent result.                                            |
| Find or open saved knowledge | `search`, `fetch`, `open_vibescroll`            | Current eligible recommendation by default; bounded history/exact version only within granted access.                           |
| Compare two analyses         | Add a narrow comparison action                  | Read-only evidence-based differences, settings/provenance and evaluation outcome; no implicit AI job.                           |
| Use or roll back a version   | Add a narrow selection action                   | Personal pin by default; expected selection revision; global changes require service authority.                                 |
| Give feedback                | `record_feedback`                               | Bind feedback to exact version and insight/evidence IDs. Never silently attach it to a newer result.                            |
| Stop new work                | Existing cancel path and supported host control | Stop further authority, preserve unknown usage and incumbent versions; never imply server cancellation proves host termination. |

Keep existing scopes for actions they already cover. Review an additional grant only for a real permission expansion. Bind every write to authenticated identity, current grant, version intent, budget and idempotency key. Do not use free-form prompts or event payloads as authorization. Preserve credentials only in the supported OAuth/MCP control channel.

The official [MCP Events documentation](https://developers.openai.com/plugins/build/mcp-events), checked October 28, specifies Work web/Cloud support, MCP 2.0 protocol `2026-07-28`, asynchronous webhooks and native subscription refresh. Keep durable subscriptions, verified signed callbacks, duplicate/out-of-order handling and current access checks. A webhook acknowledgement alone does not establish execution. The official [MCP server guide](https://developers.openai.com/plugins/build/mcp-server) recommends tools organized around recognizable user goals and allows tools without custom UI. These provider facts do not attest the requested model or grant blanket commercial/source-reuse permission.
