# VibeScroll failures, fixes and remaining prevention work

Mode: reference. Audit: October 29,2026, Europe/Berlin. Scope: this conversation and its linked local evidence, not every failure in the product's history.

Read [current state](CURRENT-STATE.md) before using a historical fix. Use the [continuation procedure](CONTINUE-VIBESCROLL.md) to act on this reference. Owner requirements have stable IDs in the [request register](../strategy/OWNER-REQUEST-REGISTER.md).

This record separates demonstrated causes, successful corrections, temporary recovery and unknown causes. A later successful run does not explain every earlier failure. Recommended prevention is not claimed implemented unless a cited test or receipt establishes it.

## Use the shorter diagnostic first

Before recreating credentials, compare a read and explicit-profile Save with implicit Save. Before repairing a cache, compare defined payload counts and RECORD self-entries. Before rerunning ASR, inspect stored segments, their API projection and actual image bytes. Check the actual host and Gateway adapter contracts instead of inventing prerequisites or borrowing another provider's behavior.

Retained evidence needs reasoning, not another downloader/runtime installation. Keep setup restrictions separate from authorized job capabilities. Retain provider responses before validation. Test the complete MCP relay and authenticated second page, not only direct mutations and first-page rendering. Use standing release authority, one spending-batch check and one current-state record. Keep exact-original reconstruction, local execution and embedded UI off the critical path.

These lessons now guide the simpler shared-preparation implementation. Their engineering acceptance remains separate from documenting them.

## Agent/process mistakes and their consequences

F42, October29: focused tests passed while the production Next build failed on a circular schema import between cloud-catalog and prepared-evidence. Keep the dependency one-way: validate/unwrap prepared evidence at the backend adapter, then pass its neutral evidence to the catalog projection. The subsequent complete build passed. Run a production build before publication; test-runner module initialization alone does not prove bundled server-page initialization.

F43, October29: the Gateway key form did not admit the attempted USD0.30 budget. The owner established that its minimum is USD1 and created that capped key. Keep provider minimums separate from the service's USD0.30 aggregate API ceiling and ten-job allowance. Confirm current form validation before repeated button attempts. Read masked-key controls and capture a newly revealed credential directly into protected storage; never put it in chat or screenshots.

F44, October29: the first real MCP quote was refused before any job/charge because the new service assumed privateOwnerId on every eligible original workspace. The owner's original sole-owner workspace uses the older creator/membership eligibility path. Preserve that workspace and wallet; bind one explicit legacy funding workspace and extend only the finite operator entitlement to its verified sole creator. Regression must reject another workspace and preserve membership/invitation checks. The generic transport error also misdirected the user toward Connections; typed preparation/credit errors remain a prevention task.

These were avoidable execution problems, not requirements to make the product more restrictive.

## Prevention backlog

Existing guards/tests above stay in the product. The following consolidated work is not implemented merely because this document exists:

1. Complete server-prepared Save routing and truthful managed/native shared publication. Remove legacy runtime repair from the normal analysis path.
2. Add one bounded correlated diagnostic view joining save occurrence, generation, preparation, evidence, attempt, event delivery, version and publication. Redact secrets/content by default and retain bounded private external responses before validation.
3. Derive or cross-check transport validators from one contract and test actual MCP 2/HTTP/backend routes. Include safe typed errors with an action appropriate to the cause.
4. Expose honest progress and a stage-specific next action. Show last activity and distinguish waiting, paused worker, unsupported source, provider refusal, terminal failure and uncertain work. Do not invent a percentage or ETA.
5. Exercise the full terminal success invariant through canonical reads: immutable output, exact transcript/evidence, real bytes, display/history, sharing, charged amount and active monitor. Add race/replay/deletion/entitlement cases to the new prepared route.
6. Version model/provider schema, tariffs, recipes and operator configuration together. Check exact supported capability before enabling a choice; retain actual/requested/host-reported provenance separately.
7. Add fair fresh-flow timing cohorts and explicit cold-user onboarding before removing experimental labels. Extend the cache-growth economics model with measured infrastructure and real behavior assumptions.

No new broad cleanup, model rerun, credential recreation, provider purchase or production race test is authorized by this reference.

## Record the next incident

Use the next stable F number and a dated private/sanitized receipt. Record these fields before calling the incident closed:

- Symptom, expected behavior, user impact and exact source/generation/attempt/commit correlation.
- Observed boundary and smallest reproducible input, with private content kept out of public documents.
- Demonstrated cause and explicitly unknown facts. Preserve rejected hypotheses and failed commands where they affect recovery.
- Correction, regression that failed before it and passed afterward, and affected adjacent paths.
- Exact local/CI/staging/production assertions. Mark skipped or unavailable observations explicitly.
- Actual versus reserved/unsettled cost, cleanup outcome, rollback and any unknown external action.
- Remaining prevention work and the requirement IDs it serves. Update current state only after verified changes.
