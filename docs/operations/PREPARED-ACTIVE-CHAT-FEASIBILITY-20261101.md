# Prepared evidence in an active chat

R137/R2 investigation, November 1, 2026. This is a capability result, not approval for hosted subscription-token inference.

## Existing supported binding

Retained reanalysis already has an exact source, attempt, evidence hash, grant version, task ID, lease and deadline. `work_cloud_input` returns the retained transcript and frame descriptors; `work_cloud_retained_frame` returns actual JPEG content and records the exact read under that lease. Completion requires the same binding and required image reads. The prepared branch needs no downloader, FFmpeg installation or transcription runtime in the chat. Contract/backend fixtures establish lease, image and stale-access behavior. Earlier native prepared-task production canaries provide separate actual-host evidence.

That does not establish a new generic first-analysis route. Fresh prepared subscription work currently checks `savedCloudRoute.available`, creates the retained attempt and requires a successful configured native waiting-event notification. A normal active chat cannot bypass that prerequisite or take over an unknown/running monitor task. This investigation therefore retains the existing route instead of inventing a no-monitor completion interface.

## Host evidence

A fresh ChatGPT chat with the original VibeScroll connection discovered its profile, listed proposals and read the newest discussion/issue without a new OAuth connection. This is actual read-only discovery/selection evidence. It is not evidence that every custom host displays native image bytes or that an arbitrary active chat can safely claim a queued task. Scripted fixtures and an image-read acknowledgment alone cannot prove visual comprehension.

OpenAI's [MCP server guide](https://developers.openai.com/plugins/build/mcp-server) supports model-visible structured results and MCP content, with server-enforced authorization. Its [Events guide](https://developers.openai.com/plugins/build/mcp-events) delivers into the subscribed chat and directs setup through Work. Its [plugin architecture](https://developers.openai.com/plugins/concepts/plugins) distinguishes packaged skills, tools and optional UI. None of those pages establishes commercial pooling of a person's subscription token or universal background execution from any chat.

## Decision

Use host reasoning for saved insights and chat-authored plans now. Use the exact existing retained/native protocol for subscription-funded video work in a verified capable host. Keep credit-funded preparation/API analysis as the independent website route. No new scopes, OAuth app, credentials, paid fallback, runtime bootstrap or active-chat promise is introduced by this investigation. A future no-monitor first-analysis interface needs an explicit delivery binding plus actual image-capable host acceptance before it can be advertised.
