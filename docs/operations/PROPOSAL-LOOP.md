# Review a post and create useful project work

Mode: how-to. ADR214 candidate, October31. This guide describes the prepared workflow; check CURRENT-STATE for actual live acceptance. It uses an already analyzed post, with no new video download or transcription.

## Website

1. Open Home, expand a saved post's project plan, or choose its suggested project to save a planning draft. All insights from the exact post are considered by default. A project profile is not proof of inspected repository code.
2. Choose Generate plan with credits. Review the displayed maximum, then start. The candidate uses GLM Flash on a no-training DeepInfra route, with at most3 existing credits held. Confirmed provider usage settles once and unused held credits return. Quoted tariffs use existing units; this does not change subscriptions or prices.
3. Keep the page open or return later. The same plan shows queued, writing, ready, stopped or usage-needs-confirmation state. Its discussion is retained. Unsent text and an unconfirmed request key survive browser reload in storage scoped to the signed-in account and proposal.
4. After choosing a credit-funded plan, write a change and use Send. Its visible reply limit applies; the message and one revision job are committed together. A failed reservation leaves the input intact. Plain comments and a host-subscription-written MCP revision remain available without a paid plan request.
5. Read the revised plan. The GitHub preflight identifies the repository and whether its issue will be public or private. Approve & create issue accepts that exact version and queues one frozen issue. It does not start coding.
6. When confirmed, use Open issue or Copy work prompt. Give that prompt to your coding assistant under your normal implementation instructions. The issue already contains authenticated feedback instructions.

## ChatGPT or Codex with the existing VibeScroll connection

Read get_project_application_context and get_project_proposal for the selected saved analysis/project. The complete retained post context is the default. You can ask your current assistant to write a proposal using the host's subscription and save_project_proposal, without starting a paid provider request.

Use get_proposal_discussion and add_proposal_message for the same retained discussion. For a paid service plan, explicitly approve quote_project_plan, then start_project_plan or reply_to_project_plan with its exact quote/version/maximum and a stable key. Read the saved state to follow progress. Never choose paid API as an implicit replacement for the user's own subscription.

For issue publication, preview_project_issue checks the current target/visibility. Only after the user explicitly approves the exact plan and creating its issue may approve_project_issue record that action. The existing GitHub integration must independently permit the repository and issue write. Legacy prepare_project_issue remains a private frozen-text handoff; it does not publish. No new VibeScroll MCP app, repeated video prompt or five-minute sign-in is required by these functions.

## Recovery

- Lost reply: retry the identical saved request/key or read the existing state. Do not start another generation or create a replacement issue.
- Stale plan/source/project: preserve the newer version and read current context. A stale generated candidate does not overwrite it.
- Unknown AI usage: the original allowance remains held. No automatic second call or alternate funding route is started.
- GitHub setup: open Connections and resolve the selected GitHub App/installation's Issues permission. Retry the existing unsent operation after setup.
- Unknown GitHub publication: Check existing publication searches for the frozen marker and exact body. An absent match is not permission for another POST.
- Outcome: the implementing assistant uses report_project_outcome through its authenticated VibeScroll connection. Model reports, signed GitHub state, CI/merge and actual user benefit are distinct evidence.

The full plan page remains available for advanced review. Library Tree/Folders, saved analyses, shared versions and original source data are preserved. The operator must complete the recorded live canaries and provider/funding checks before this candidate is described as production-ready.
