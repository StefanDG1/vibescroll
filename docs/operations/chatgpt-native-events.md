## How authentication and renewal work

ChatGPT is the OAuth client. WorkOS authenticates the VibeScroll user and issues scoped, resource-bound credentials. ChatGPT keeps the provider credentials and refreshes authenticated access. VibeScroll validates the bearer signature, issuer, resource audience, expiry, registered client, scopes and current provider identity. The same WorkOS subject identifies the existing VibeScroll user, rather than creating a shared database login.

The backend separately checks current workspace membership and the user's VibeScroll grant. That grant limits library access and permitted actions and can last until revoked. The database remains private. A valid OAuth token cannot bypass a revoked app grant or another workspace's authorization.

The native monitor subscribes through MCP Events. VibeScroll verifies callback ownership, encrypts the finite delivery credentials and rechecks current permissions before delivery. ChatGPT renews before `refreshBefore`. The server keeps its maximum thirty-minute lifetime and earlier OAuth/grant-expiry bound. In the live test the original expiry was about five minutes, and automatic renewal extended it without user interaction. An until-revoked app grant, short-lived OAuth access and a renewable event subscription are three separate lifetimes. Disconnects, revocation, provider restrictions or invalid credentials can still require reconnecting.

The serving code uses `@modelcontextprotocol/server` 2.3.1. Modern wire tests use revision `2026-07-28` and exercise `server/discover`, `events/list`, `events/subscribe` and `events/unsubscribe`. These are native protocol methods, so they need not appear as ordinary model tools. The live account successfully used the native lifecycle; its exact negotiated wire revision was not separately captured.

## Automatic app saves candidate: exact one-time setup

This section describes the unpublished ADR162 candidate. The serving three-option picker and illustrated guide are sourceff7d88f; its own-Cloud analysis choice remains disabled. The native setup task has not passed decoder admission. These steps are not a claim that automatic media is available to customers.

1. Install the operator's existing registered VibeScroll plugin and authorize your own account once. Keep the original connection. This candidate adds no OAuth scope. Supported OAuth refresh and Events renewal are separate from the app grant; neither promises validity forever.
2. In your private library's Connections, review the all-posts grant, exact private Cloud requests, status/Events/analysis actions and the separate automatic-app-Save checkbox. Review its model, effort and result retention defaults. Use Until revoked if that is the access you intend. An older grant does not acquire these defaults automatically. Changing sensitive permissions can require a recent app sign-in; ordinary later saves use the reviewed grant.
3. In a supported ChatGPT Work chat with Cloud selected and VibeScroll enabled, complete actual tools, pinned package, image and isolation readiness before any source job. GitHub and a paired computer are unnecessary. An installed executable or successful event reply is insufficient. Do not bypass refused controls or repeatedly reconnect OAuth to try to fix a runtime error.
4. Create one native `video_link_saved` monitor for that private profile and current grant version. Its action reads the exact post's `get_job_status`; ordinary save-only events stop after acknowledgement. Only a current `saved_cloud_intent` permits the automatic branch. The host preflights before calling `request_analysis` with `mode=work_cloud` and `savedIntentId`, with no settings overrides. It then reuses the existing exact claim, input, preparation, JPEG uploads and completion. Let monitor setup finish; do not add polling or manual Run now as wake evidence.
5. Choose My own Cloud Work in app setup or Save. The picker permits handoff only with one current reviewed connection and an active saved-link monitor. Save one permitted Reel or TikTok link with analysis selected. The app opens the saved post; Waiting for ChatGPT describes an intent, not a running job. A finite expired intent requires review; ready/claimed/unknown work stays intact. Save without analysis is always separate. No credit or local fallback is selected automatically.
