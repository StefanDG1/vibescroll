## What worked

An official user-owned Cloud task on the existing subscription acquired one real, previously unanalyzed saved Instagram Reel. It decoded a 46.9-second video, ran offline CPU transcription, inspected eight sampled frames through native image view, and produced timestamped neutral claims and interpretations. A separate offline quality review read all eighteen transcript segments and inspected two ending frames, for ten actual frame views total. It completed in 157.250 seconds from dispatch without new network work. Independent listening, intervening imagery and the final approximately 0.40 seconds remain unchecked. No Docker Desktop or awake paired computer executed this test. No paid model API, purchased credits or VibeScroll-managed processing service was used.

The task did not trigger from a VibeScroll event, claim an app analysis lease, return a canonical app result, publish an insight, or process for another user. The older Cloud checkout supplied media helpers; local application validation at `94ad168` is separate evidence. Private source identifiers, content, transcript and result remain outside the public receipt.

## Networking corrections

The executor has no general Internet route. The installed runtime networking instructions require the inherited proxy, configured CA trust and current supported status. Require `observations_current`, matching executor/revisions, restricted mode and `enforced` before traffic. A startup policy file or an earlier enforced observation is insufficient. Observed enforcement varied without configuration changes by this run; the final unknown state permitted no further network work.

The first source invocation failed because a task-local safety filter attempted executor DNS. The corrected loopback filter validates HTTPS port 443 and approved hostname boundaries, rejects IP literals and malformed authorities, and forwards only through the inherited sidecar. The sidecar resolves origin DNS. Offline tests covered eighteen rejected and four accepted cases. There is no direct-origin or `NO_PROXY` fallback, cookie import, new host or access-denial bypass.

A second invocation retrieved metadata but failed CDN certificate verification. The pinned downloader documents [`--compat-options no-certifi`](https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/README.md) to select system trust. Offline inspection of the actual pinned binary confirmed that selection uses the existing runtime CA bundle with `CERT_REQUIRED` and hostname verification enabled. A third explicitly recorded invocation succeeded. No unknown CA was added and certificate verification was never disabled. This TLS trust configuration is separate from signing a Windows installer; the personal Cloud test required no code-signing certificate.
