## Deliberately deferred changes

A full source-content split is the largest architectural option left after this candidate, particularly if libraries and analyses grow. Separating transcripts/analysis from source metadata could reduce list reads and index copies. It touches every pipeline, source correction, search, deletion, export and restore path. The current 81.62 MB recent library read total does not justify shipping an unverified rewrite with this release.

Hourly retention still visits historical rows. A separate indexed retention queue can eliminate those scans, but must reliably enqueue legacy records and cover restores and interrupted cleanup. This candidate removes the heavy manifest dependency and repeat empty writes first.

Issue reconciliation's global history page and unbounded export/revocation collections remain scaling concerns. Recent `issues.reconcilePage` I/O is only 271.64 KB. Owner-driven full exports are intentionally content reads. Add indexes or queues only where the observed history/workload warrants their own lifecycle tests.

No blanket cron disabling, backup thinning, loss of private evidence, weakened authorization, budget increase, shorter retention or blind retries are part of this audit.

## Evidence and next measurement

Production baseline probes return only counts, field sizes, authority values and manifest digests. They are bounded, read-only queries. One initial multi-table pagination probe failed because Convex permits one paginated query per transaction; it was replaced by bounded independent table probes. Local failures are retained rather than reported as passes.

Local tests establish migration and policy behavior, not production savings. After exact deployment, compare manifest hashes and unchanged SHA/profile/selection/timestamps, upgrade source authority, validate card/canonical consistency, and measure matched read/query payloads. Check the next daily breakdowns under similar workload. The audit cannot guarantee future usage or an exact invoice reduction from a single partial-day snapshot.

The corrected production baseline at 20:32-20:33 UTC reads all six canonical repositories in a bounded ten-row query: 1,031,204 database-read bytes and 1,064,160 JSON characters. One matched source read consumes 19,759 database bytes. Transaction metrics distinguish database bytes from JSON length. Local acceptance and retained probe/test failures are recorded in [implementation status](../implementation-status.md).

After deployment at approximately 20:36 UTC, the same six repository records read 88,868 database bytes, a 91.4% reduction. All manifest digests, repository SHAs, profile/selection versions, timestamps, enabled and confirmed flags matched the baseline. One matched source authority read fell to 745 database bytes, a 96.2% reduction, with identical identity/workspace/state/generation. All 250 production source records passed card consistency checks across 26 bounded pages. Development also received the compatible main backend: one repository and 18 sources passed side-record/card binding checks. Its deployment additionally installs six indexes from earlier main releases; no index was removed.
