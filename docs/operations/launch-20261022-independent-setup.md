# Prepare an independent Windows setup observation

Mode: how-to. Prepared October 22, 2026. This protocol schedules no session, contacts nobody and starts no processing or spending. No independent participant or completed result is claimed.

Use this with the [independent-use study](independent-use-study.md), [personal runner instructions](personal-analysis-runner.md), [package reference](../../packages/companion/README.md) and [launch acceptance matrix](../launch-plan/2026-10-22/ACCEPTANCE.md). The study requires two clean-checkout personal testers and one retained-data upgrade. A single technical session supplies evidence only for the steps actually observed.

Do not buy a certificate or service to complete this protocol. Keep general commercial hosted ChatGPT-plan access, unapproved source providers and Windows coding behind their existing gates.

## Operator preparation, without dispatch

1. Choose a consenting adult participant who controls their own Windows device and eligible model-provider account. An operator's second account is not an independent participant. Retain consent privately under an opaque study ID; publication of their words or screenshots needs separate permission.
2. Record the exact application, backend, checkout commit and runtime versions to be tested. A documentation commit can differ from the serving build. Give the participant the public Help and this protocol, not private founder configuration or credentials.
3. Confirm the intended workload is permitted for that participant and deployment. Provider approvals remain pending where recorded. Do not infer eligibility from the founder's success or activate commercial access. Any restricted personal-alpha enrollment needs a verified account subject and explicit operator review; email matching and a UI preference do not establish eligibility.
4. Select one short source the participant owns or has permission to process. For a text canary, retain the exact UTF-8 input hash, revision/attribution and applicable licence notice. Reading a public URL does not automatically establish redistribution rights. Keep the source private unless a later exact publication is approved.
5. Review the cumulative task ledger before any hosted request or worker start. The ceiling is **US$2 total including all prior task activity**, not US$2 per tester or US$2 still available. The root must reserve the actual remaining request, refresh, worker, inference and cleanup bounds first. Missing settled invoices do not mean unused budget. If headroom is insufficient, leave the session pending. This document grants no hosted dispatch authority.
6. Account for the actual UI call graph. Computers and source pages can load broad workspace data, successful writes refresh it, and visible pages poll immediately and periodically. A worker also polls and sends job heartbeats. Reserve authentication redirects/bootstrap and exact static resources. Do not navigate repeatedly to discover the cost after dispatch.
7. Keep any task browser guard stopped until its exact-build resources, request limits and phase are reviewed. Foreign authentication hosts need a separately reviewed phase; do not add broad exceptions to make sign-in pass. Intentional refresh blocking must be recorded as a test limitation, not an uninterrupted UI success.

Do not create cloud infrastructure, a merchant account, billing products, public collections or new paid usage for this observation. Preserve the participant's unrelated work, browser sessions, containers and existing protected connection.

## Participant preparation on Windows

The technical source-checkout route needs the reviewed checkout, project's pinned Node 24 runtime and package manager, a working local Docker Desktop Linux engine, the pinned official-client image and a supported own-account connection. It is not an all-local inference route: approved source text goes to the model provider.

Use the [local development instructions](../local-development.md) for the pinned dependency setup. Inspect the exact source version before executing it. Review any project-scoped downloads and their sizes first. Stop if a system upgrade, Docker restart/reset, administrator access, paid top-up or unrelated worker shutdown appears necessary. No such action is authorized by this protocol.

Use a new private configuration only when no correct existing configuration is available. Follow the [personal runner instructions](personal-analysis-runner.md) for its fields and protected storage. The configuration names the participant's workspace and Windows Credential Manager target; it contains no OpenAI token or API key. Keep installed configuration outside the installation tree, and preserve any existing absolute `VIBESCROLL_COMPANION_CONFIG_ROOT`. Never copy the founder's credentials or override host `HOME`/`CODEX_HOME`.

Once execution is separately reserved and authorized, these are the supported source-checkout commands. Replace the example with the actual private absolute configuration path; do not paste that path into a public report.

```powershell
node packages/runner/pair.mjs "C:\absolute\private\config.json"
node scripts/companion.mjs preflight "C:\absolute\private\config.json"
```

Pairing creates a local device credential and public request. Do not rerun it against an already paired configuration: it refuses an existing credential target. In the normal signed-in app, choose the participant's workspace, then **Account → Computers**. Paste **Public pairing request**, choose **Review device request**, compare the terminal fingerprint and choose **Confirm matching computer**. Both pairing actions need sign-in within five minutes. Complete normal WorkOS sign-in/MFA when requested; never replace it with an admin acting-as identity.

The preflight report checks local prerequisites without opening account credentials, contacting providers or starting a worker. It returns `processingReady: "unverified"`. Its full companion checklist includes media dependencies even for a text-only observation. Record every blocked/unknown check. A missing media dependency is not evidence of failed text processing, but it also cannot be hidden as a fully ready companion installation.

For an explicitly reviewed text-only developer run, the personal runner still requires the protected official-client image, local Linux Docker named pipe, correct paired workspace/device and eligible official account. Media transcription dependencies remain a separate media acceptance task. Do not weaken the full companion preflight or launch its assistant-intake worker to bypass a blocked prerequisite.

## Connect the actual personal worker

After the operator reserves the bounded worker session, run:

```powershell
node packages/runner/personal-runner.mjs "C:\absolute\private\config.json"
```

This entry point starts its own isolated `--personal-library` official controller. Do not separately start a second controller, remove its lock or stop an existing user worker to force access. If the protected connection cannot be reused, follow only the official device-code flow it offers. The participant enters their own consent; keep login codes and tokens out of recordings and reports.

The worker must advertise an actual account model and current profile to the matching backend. A saved connection, local prerequisite report or legacy `LocalChatGPT` status does not prove this. In the app, the computer must be owned, paired, online within 60 seconds and show its available model list. Do not assume that every account offers the model used in the founder canary.

Keep the computer awake. Stop if a quota, permission, profile or connection check fails. Do not switch to an API key, cloud credits or another person's plan. Started work may consume the participant's plan allowance even if canceled.

## Complete one real supplied-text task

1. Choose **Save** and **Supplied transcript**. This is the current form label for the plain text route. Give a non-transcript source an accurate title such as a supplied README excerpt with its revision. Paste the permitted text and attribution; confirm the actual submission rights. Save without automatic cloud processing.
2. Open that source. Under **Use your ChatGPT plan**, select the participant's own online computer and an actually advertised model. Check the source-specific medium-reasoning own-plan consent, then choose **Analyze with my plan**. Approval requires a sign-in within five minutes; **Sign in again** preserves the return path. An unclaimed approval expires after 15 minutes.
3. Wait within the reserved duration. Do not approve a second source or retry an uncertain result. Read the existing source state before deciding what happened. Text-only processing uses no media-preparation credits; platform requests and provider allowance are still real resources.
4. On a ready result, ask the participant to explain one claim, its interpretation and a warning. Open its **Supplied text** reference or original-text section, compare the actual passage and identify an omission or uncertainty. Untimed user-note citations do not verify repository lines, direct retrieval, audio or video.
5. Ask the participant to return to Library, find the same result and explain saved, waiting, failed and ready states. If the reserved UI flow blocks an automatic refresh, record the intervention and affected step rather than claiming unaided completion.
6. Stop only this test's foreground worker with Ctrl+C and let its own controller clean up. Record whether cleanup completed. Do not kill unrelated processes or delete an uncertain lock. Any optional disconnect, source deletion or device revocation needs its own bounded action and consent; do not delete the participant's app account as routine cleanup.

Do not connect GitHub as a coding destination, evaluate a repository, publish an issue or run code from the supplied source. Those are separate tasks. Public publication of the founder's seven-insight canary remains subject to human content/rights review; this protocol does not approve it.

## Record evidence and stop conditions

Keep raw records private and redact them before sharing. Record:

- Opaque participant ID; own-account/device confirmation; consent scope; role and chosen path.
- Checkout/serving/backend versions; Windows/runtime versions; actual advertised model and effort.
- Prerequisite outcomes, actual download sizes, active setup time, approval waits, errors, wrong turns and every operator intervention.
- Input UTF-8 hash/byte count; genuine approval; source state/generation; validated output; citation kinds, warnings and the participant's source comparison.
- Desktop/mobile viewport or physical-device identity at an appropriate non-identifying level; keyboard/focus, text readability and overflow observations.
- Request/worker counts, reservations, measured receipts and unknown settlement. Preserve failed, canceled, blocked and duplicate attempts.
- Cleanup outcome, remaining protected connection/device state and any deliberately retained private source.

No passwords, login codes, tokens, email addresses, account/workspace/device/source IDs, private paths or raw private source content belong in committed evidence. A visible error and sanitized description are sufficient for a public issue.

Mark each task **passed**, **failed**, **blocked**, **assisted** or **not attempted**. Keep the signed-distribution row blocked while signing trust is unavailable. Keep a provider-dependent task blocked until that exact approval exists. A developer source run cannot close signed customer installation, startup at sign-in or staged update/rollback acceptance.

For the later upgrade observation, first obtain an actually supported, reviewed upgrade artifact and independent participant consent. Preserve configuration, credentials, authored notes and deletion markers; test retained-data compatibility and explicit rollback within its own reservation. Do not lower the signature/trust floor or substitute an unsigned artifact. Record this row as pending today.

Independent source inspection can establish comprehension of that source. It does not supply a held-out quality benchmark, measured time saving, demand, payment evidence or whole-plan acceptance. A failed or declined session is valid evidence; do not invent a replacement participant or testimonial.
